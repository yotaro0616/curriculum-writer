# 設計前調査（G1）

教材の設計判断（/define・/outline）の根拠を先に揃える。**裏取りの責務はこのフェーズが持つ**。/outline は見出し骨子をこの調査に基づいて組み、/write は成果の参照と差分確認に留まる（執筆時に初めて調べる、を無くす）。

**入力**: $ARGUMENTS

**成果物**: `RESEARCH.md`（リポジトリルート。`docs/` は /github-pages のビルド出力と衝突するため使わない）

**完了ゲート**: G1 = ユーザーが調査結論を承認 → `PROGRESS.md` に記録

---

## Phase 0: TOPIC とスコープの確定

調査対象を固める。ここが曖昧だと調査も WHO/WHY/WHAT の深掘りもぼやける。

聞き取る内容:
- **TOPIC**: 何を教えるか（例: Vercel デプロイ、Laravel、Docker）
- **スコープの外縁**: 含むものと含まないもの
- **対象技術の確定**: 具体的なツール・フレームワーク・バージョン
- **公開方式**: GitHub 直読み / GitHub Pages（MkDocs Material）/ Zenn・Zenn 互換レンダラの LMS / その他 LMS 等（表現様式の決定材料。確定は /pilot。LMS の場合は **Markdown レンダラの方言**（Zenn 記法・admonition・素の CommonMark のどれが描画されるか）まで確認する）

深掘りの例:
- 「○○まで含めますか？それとも○○に絞りますか？」
- 「読者がこの教材を終えた後、次に学ぶべきことは何ですか？（＝この教材のスコープ外）」

**スコープ変更の検知**: 以降のフェーズでユーザーの回答がここで確定した TOPIC・スコープと矛盾する場合、Phase 0 に戻って再確認し、影響を受けるフェーズを再実行する。

TOPIC とスコープをユーザーに提示し、承認を得てから Phase 1 に進む。

## Phase 1: 調査

組織・案件固有の前提（事業・受講者・現場スタック・NG 用語・制約）があればユーザーから受け取り、調査の前提にする。以下を並列に調査する。**すべての項目に出典（URL / 書籍名）と確認日を付ける**。

1. **公式ドキュメント体系**: 目次構造・対象バージョン・リリースサイクル・変わりやすい領域（→ /check-updates の重点対象になる）
2. **トピックマップ**: 公式ドキュメントの機能一覧から、教材が扱いうるトピックを階層で列挙する（/outline のカバレッジ突合の基準になる）
3. **競合・既存教材**: 定番の構成・到達点・差別化の余地
4. **題材候補**: ハンズオン・やってみように使える題材（環境要件・無料枠・再現性・陳腐化リスク）
5. **読者仮説の裏付け**: 想定読者の実像（コミュニティ・求人・Q&A サイトの頻出課題等）

**既存資産がある場合（旧教材・社内資料・組織固有の資料）**: ギャップ分析を追加で行う。既存資産と新教材のゴールの差分を一覧化し、3アプローチ（**Extend**: 既存を拡張 / **Create New**: 新規に作る / **Restructure**: 再構成する）を When / Pros / Cons で比較して推奨を RESEARCH.md に記録する。

## Phase 2: RESEARCH.md の生成

構成:

1. TOPIC・スコープ（Phase 0 の承認内容）
2. 対象バージョンと確認日
3. トピックマップ（階層リスト）
4. 題材候補（比較表: 題材 / 環境要件 / 再現性 / 向く用途）
5. 読者仮説と根拠
6. 変わりやすい領域（/check-updates の重点）
7. **未確認・書かないこと**（裏が取れなかった事実・意図的にスコープ外にした話題のネガティブリスト。執筆時の混入を防ぐ）
8. **未解決論点**（調査では決められず、ユーザーの判断を仰ぐ点）

ドラフト → 自己レビュー（修復は最大2周。裏が取れなかった事実は 7. へ、ユーザーの判断を仰ぐ論点は推測で埋めず 8. へ列挙する）→ 提示。

## light モード（適応的深度）

小規模教材・書き手が熟知しているトピックでは `light` を使う: 上記 1・2・6・7・8 のみ（主要資料の目次・版・変わりやすい領域だけ）。/setup が規模に応じて提案する。省略・軽量化の判断は `PROGRESS.md` の adaptive に記録する。

## 完了

未解決論点への回答を得て RESEARCH.md を確定し、承認を得たら `PROGRESS.md` の `G1_research` に日付を記録する。次は `/define`（哲学の定義）。
