# 教材のレビュー

問題点は自動修正せず、すべて報告のみとする。

**入力**: $ARGUMENTS

## スコープの解釈

CLAUDE.md の HOW セクションで定義された階層構造に基づいてスコープを判定する（`/write` と同じルール）。

## 0. 並列化（上位スコープの場合）

上位スコープの場合、グループごとにサブエージェントを並列起動する。各サブエージェントには OUTLINE.md の該当部分、対象ファイルパス、レビュー観点と出力フォーマットを渡す。

各サブエージェントの結果を統合し、横断整合性チェック（セクション3）はメインで実行する。

通し読みの観点（公開前ゲート・パイロット検証）が必要な場合は `.claude/agents/learner-persona` を起動し、前提知識だけの読者としての通読レポート（つまずき・未定義用語・例示/実践の混乱）を結果に統合する。

## 1. 準備

1. `OUTLINE.md` を Read し、対象スコープのゴール・Section 構成・参考資料を確認
2. `PROGRESS.md` の config を読み、**style が emoji 以外なら `styles/<style>.md`、section_model が weave なら `section-models/weave.md`、verification_model が ai-delegated なら `verification-ai-delegated.md`（いずれも `.claude/skills/write/references/` 配下）を Read する**（読み替えが writing.md より優先。並列レビューのサブエージェントにもパスで渡す）
3. 対象スコープと前後の Section ファイルを Read
4. OUTLINE.md に記載された参考資料を取得する。**ローカルファイルパスは Read ツールで読み込む**。URL がある場合は WebFetch で取得する。教材の記述内容と参考資料の実態を照合するために使用する

## 1.5 機械的チェック（Grep/Bash ベース）

サブエージェント起動前に `python3 scripts/lint_curriculum.py <対象ファイル>` を実行する（検出パターンの正はスクリプト側。/write のセルフチェック・PostToolUse hook と同一の検査。様式・アークモード・検証モデル等の執筆判断は `PROGRESS.md` frontmatter の `config`（決定録）を正とし、lint の様式は `config.style` から自動適用される）。結果をサブエージェントに渡し、重複チェックを避ける。

スクリプトが扱わない OUTLINE 連動の2項目は、ここで Grep ツール（ripgrep ベース）を使って検証する（Bash の `grep` は macOS 互換性の問題があるため使用しない）:

| ルール | 検証方法 |
|---|---|
| 前提知識の欠落 | OUTLINE の `前提:` フィールドを持つ Section に `📝 **前提知識**` があるか確認（🟡） |
| 接続文のキーワード | 各 Section 末尾の接続文が OUTLINE の次 Section ゴールキーワードを含むか確認（🟡） |

機械的チェックの結果は lint の重要度をそのまま用いる（🔴 = exit 2 のブロッキング違反 / 🟡 = 構造警告）。上の Grep 2項目（前提知識・接続文）は設計不整合として 🟡 で報告する。

## 2. 単体レビュー

以下の5観点で検証する。各観点の具体的なチェック項目は `.claude/rules/writing.md` を参照すること（ここでは重複して列挙しない）。

### ルール準拠

`.claude/rules/writing.md` に定義された文体・テンプレート・コンテンツ規則に準拠しているか

### 設計との整合

`OUTLINE.md` の設計（Section 構成・ゴール・種類）と実際の内容が一致しているか。見出し骨子が充填済みの Section では、実際の `##` 見出しと骨子の乖離（書き戻し漏れ）を検出する（🟡）

### 正確性

教材の用語・内容が参考資料の表記に従っているか

> 📝 参考資料との詳細な照合は `/check-updates` の責務。

### 実践フォロー可能性

🏃 実践・ハンズオンを含む Section が対象。以下を検証する:

- **状態の追跡**: 各ステップ実行後の Git 状態・ファイル状態が、次ステップの前提と矛盾しないか
- **コマンドの正確性**: そのステップの時点の状態でコマンドが期待どおりに動作するか
- **前提条件の明示**: 📌 チェックリストで実行前の必要状態が網羅されているか
- **副作用のクリーンアップ**: 実践で変更したリソースを元に戻す手順が含まれているか
- **位置ルール**: 学習者に実行させるコード・コマンドが**実践見出し**（emoji: 🏃 見出し / 他様式: `実践:` `Step N:` `やってみよう:` 見出し。正規形は lint が検査）の配下以外に置かれていないか（writing.md「例示コードと実行コードの区別」）。weave では役割行（**入力** / **実行** / **読む例**）の妥当性（読む例が本当に読む例か・入力の対象パスと操作種別が正しいか）も見る
- **構成形との整合（weave）**: 混合 Section の構成形（二段 / 織り込み）が OUTLINE の種類注記（無印は section_model の既定）と一致しているか（🟡）
- **検証モデルとの整合**: AI委任型ハンズオン（`config.verification_model` = ai-delegated。基準は writing.md「ハンズオンの検証モデル」）では、コマンドの正確性・状態の追跡は固定層のみを対象にし、達成判定は観察できる達成状態で行う。流動層（AI 生成物）に「一例」の明示があるかを確認する

> 💡 コマンドの実機検証が必要な場合は `.claude/agents/handson-verifier` をサブエージェントとして起動する（一時ディレクトリで 🏃 のコマンド列を順に実行し、記載の出力・✅ の達成状態と突合する）。

### 文体・AI 臭

`references/ai-slop-curriculum.md` の観点で検証する（構造・語彙・立場の3グループ＋🧠 コラム専用基準）。表層パターン（記号・強調の書式等）は機械チェック（1.5）が、語彙・🧠・採点は /write のセルフチェックが先に通しているため、**ここでは談話レベル**（命題型見出し・両論併記による判断放棄・リズムの均一さ・擬人化ドラマ等）**に集中する**。テンプレート・様式が要求する定型ブロック（観察文・📌 / ✅ の状態契約・役割行・確認問題の枠）は「リズムの均一さ」の指摘対象にしない。Section 単位の総合判定には同ファイルの採点5軸を使ってよい。

## 2.5 変更スコープモード（/revise の検収）

/revise の適用後に呼ばれた場合、`changes/<slug>/` を Read し、通常観点に加えて3軸で検収する:

- **網羅性**: `changes/<slug>/` の tasks.md が全消化され、outline-delta.md の全項目が**本文に**反映されているか（OUTLINE 本体への反映は `--archive` のマージが担うため、ここでは delta と本文の一致を見る。量産ループのタスクリスト＝PROGRESS 進捗表とは別物）
- **正確性**: 変更後の本文が新しい OUTLINE のゴールを満たすか
- **整合性**: 接続文・初出参照・用語・グループ全体像テーブルが変更をまたいで一致しているか

指摘は通常どおり 🔴🟡🔵 で報告し、適用の最終判断はユーザーに残す。

## 3. 横断整合性チェック

> 対象スコープ外に既存コンテンツが存在する場合のみ実行。

- 用語の一貫性、文体の統一、Section 間の接続の自然さ
- リンク・参照先の実在確認、セクション番号の整合

## 4. 出力

```
**[スコープ] レビュー結果**: 指摘 X 件（🔴 X / 🟡 X / 🔵 X）

## 修正アクションリスト

| # | 重要度 | ファイル | 箇所 | 修正内容 |
|---|---|---|---|---|
```

重要度: 🔴 ブロッキング（技術的誤り・ゴール逸脱／機械チェックが exit 2 で止める書式・構造の破れ） / 🟡 設計不整合・構造警告 / 🔵 軽微なスタイル問題
