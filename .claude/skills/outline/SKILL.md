# 構造設計（G3）と見出し骨子の JIT 充填

**入力**: $ARGUMENTS

2つのモードがある。引数に Chapter 番号があれば モード B、なければ モード A。

---

## モード A: 骨格設計（→ G3）

CLAUDE.md の WHAT / HOW を OUTLINE.md の構造に分解する。

**準備**: `CLAUDE.md` と `RESEARCH.md` を Read（RESEARCH.md が無ければ根拠の弱さをユーザーに伝えたうえで進める）。

### 分解の手順

1. 階層構造に応じて WHAT を分解する（3層: WHAT → Part → Chapter → Section / 2層: → Chapter → Section / 1層: → Section）
2. 各 Section に種類を付与する。基準は `config.section_model` に従う（separate: writing.md「Section の種類と学習モデル > 使い分けの判定」/ weave: `section-models/weave.md` の判定表＝既定は混合（織り込み）・概念は Chapter 0〜1 目安で超過は種類方針に理由を明記）。やってみようを置く概念は「概念（やってみよう: 題材）」、構成形を既定から変える混合は「混合（二段）」等と注記
3. **ペーシング検査**（section_model 別）: separate = 実践接点（やってみよう・混合・ハンズオン）の無い概念 Section が3連続以上並んでいないか（例外は種類方針に理由を明記）/ weave = 各 Chapter に非タイピング接点（概念 Section または「接点: 想起まとめ」を注記した節）が最低1つあるか。weave では Section の目安時間の Chapter 合計を出し、/define の学習時間モデル・教材全体の想定学習時間と突合する
4. Section 間の依存を `前提:`（後方 Section ID のみ）で明示。重複・越境しやすいトピックは `扱わない: ○○（→X-X-X で扱う）` で境界を宣言する
5. 参考資料を紐付ける（RESEARCH.md の出典を正とし、バージョン・確認日を併記）

### MECE 設計原則

| 原則 | チェック |
|---|---|
| **階層的 MECE 分解** | 上位を漏れなく・重複なく分解しているか |
| **抽象度の一貫性** | 兄弟要素は同じ抽象度か |
| **各レベル 2〜4 個** | 5個以上ならグルーピング不足を疑う |
| **分解軸の単一性** | 兄弟が同じ軸上にあるか |

### カバレッジ突合（RESEARCH.md との照合）

RESEARCH.md のトピックマップと OUTLINE 案を突合し、次の3分類の表を提示する:

| 分類 | 意味 |
|---|---|
| 網羅 | トピックマップにあり、OUTLINE のどこかで扱う |
| 意図的除外 | 扱わないと決めた（理由を1行で） |
| 漏れ | 検討されていない（→ 扱うか除外かをユーザーが判断） |

**数値情報の検証**: ゴールや説明に具体的な数値（「70+ コマンド」等）を含める場合は、参考資料を確認して正確な値を記載する。概数は「約」を付ける。

実践プロジェクトがある場合は、使用箇所・依存関係・各 🏃 実践の概要も設計する。付録の**枠**を末尾に置く（行の充填はモード B・/write・/lecture plan が担う。ハンズオンの共通方針・執筆ノートは全モデル共通。**やってみよう表の枠は separate のみ**＝weave では作らない）。

ドラフト → 自己レビュー（最大2周。真の曖昧さは推測せずユーザーへ）→ 提示。**このモードでは見出し骨子を書かない**（骨子は執筆直前にモード B で充填する）。

承認を得たら `PROGRESS.md` の `G3_outline` に日付を記録し、Section 一覧を PROGRESS の進捗表に展開する（全列空欄で展開する。図・動画列の `-`（対象外）は、メディア方針が /pilot の config で確定した後に /status が同期する）。次は `/pilot`（試作と様式ロック）。

## モード B: 見出し骨子の充填（`/outline 2-1`）

対象 Chapter の執筆直前に、各 Section の設計を執筆可能な粒度まで下げる（1層教材は Chapter が無いため、Section 番号・範囲の指定でこのモードを起動する）。**チャットに揮発していた「方針合わせ」の成果を OUTLINE に永続化する**フェーズ。

1. **裏取り**: RESEARCH.md と対象 Section の参考資料の該当箇所を実取得し、見出しに現れる事実（機能名・コマンド・記法・バージョン固有の挙動）を verbatim 確認する。参考資料フィールドの確認日を更新する
2. **充填**: 各 Section に次を書き込む:
   - `見出し骨子:` — writing.md「見出しの設計」（規律5項目・選択済みアークモード。weave の混合は `section-models/weave.md` の開始アーク＋トピック見出し）に従った `##` 見出しの列。見出しに現れる事実には出典を添えてよい（素材の対応が明確だと執筆時の fresh-reference が速い）
   - `依存:` — `←` 先行 Section から引き継ぐ状態・成果物 / `→` 後続 Section が参照するもの（接続文・初出参照・成果物受け渡しの根拠になる）
   - `終了状態:` — 状態を引き継ぐ種類（ハンズオン / 混合）のみ（ブランチ・作成物・起動状態。次 Section の 📌 と突合する。weave では実質必須）
   - 混合の構成形（二段 / 織り込み）が既定と異なる場合はここで確定して種類フィールドに注記する
   - `画面:` — 主要な画面キャプチャポイント（config.capture を使う教材のみ・任意。/write が 📸 コメントに展開する）
   - やってみようの有無と題材（separate のみ。付録「やってみよう表」も同時に更新。weave では N/A）
3. **提示・承認**（軽ゲート）: 骨子一覧をユーザーに提示し、承認を得たら `PROGRESS.md` の該当 Section の「骨子」列に日付を記録する

### 規律

- **バックフィル禁止**: 執筆しない Chapter の骨子は書かない。既存教材への導入時も、/revise の対象になった Chapter だけ充填する
- **書き戻し同期**: 執筆で骨子から外れた場合、/write が本文の完成と同時に骨子を実態へ書き戻す（設計と本文を乖離させない）

## 再設計（G3 承認後の構成変更）

- 未公開で、影響が対象 Chapter 内に閉じる場合: このスキルで直接編集してよい（変更点をユーザーに提示して承認を得る）
- 公開後、または複数 Section にまたがる場合: `/revise`（変更管理フロー）を使う
