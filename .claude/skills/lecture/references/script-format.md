# 授業動画の台本書式と収録規範

`/lecture script` が生成する台本（`lecture/<sectionId>.md`）の書式・執筆規範・収録チェックリストの正。

> 設計根拠: Guo, Kim & Rubin 2014（edX 690万セッション: 視聴継続の中央値は動画長によらず最大約6分・9分超で半減・チュートリアル動画は Step 境界でポーズされ再視聴率が高い・自席のインフォーマル収録がスタジオ収録に勝る）/ Mayer のマルチメディア原理（Segmenting・Redundancy＝画面の文を読み上げない・Personalization＝会話調）/ 講師映像の研究（動機・社会的存在感を高めるが、新出の図・コードへの注視を遅らせる）/ 2カラム AV スクリプト（Celtx の AV script template 解説）と日本の構成台本（尺・ナレーション・映像指示・テロップ。KIC Factory の動画台本解説等）の慣行。

## ファイル書式

```markdown
---
section: 2-1
title: [Section タイトル]
本数: 2
合計尺目安: 9:30
作成日: YYYY-MM-DD
本文基準日: YYYY-MM-DD   # 基準にした本文の最終更新日（/lecture が要更新判定に使う）
---

# 収録メモ

- 初期状態: [Section の 📌 と verified スタンプから導出。ブランチ/タグ・起動しておくもの・開いておくファイル・実施済みの Step]
- 素材準備: [貼り付け用スニペット・完成版ファイル・表示する図。assets/ の図はリポジトリルートからのパス（assets/diagrams/output/…）で書く（本文の相対パス ../../ 形式をコピーしない。台本は lecture/ 直下にあり階層が異なるため）]
- 素材命名: 2-1_scene04_take02.mkv 形式（Section 番号_シーン_テイク）。複数本の場合は動画 1 も含め全動画に -vN を付ける（2-1-v1_scene01_take01・2-1-v2_scene01_take01）

# 動画 1/2: [この動画の学習目標をタイトルに]（尺目安 5:00）

## シーン 1: [サブゴール]（目安 0:40・約170字）

- 画面: [何を映すか。エディタ（ファイル名）/ ブラウザ（URL・画面名）/ ターミナル / スライド・図]
- 操作: [講師が行う操作。本文の Step 番号と対応させる]
- ワイプ: 通常 | 縮小 | 非表示 | 顔全画面
- テロップ: [任意。強調したいキーワードのみ]

**トーク**:

[話し言葉のフル文。そのまま読み上げられる完成文で書く]

**要点**:

- [ライブ進行用の箇条書き。何を見せ、何を言うかの骨子 2〜3 行]
```

- **トークと要点は併記する**（フル文 → 一言一句読む運用にも、要点だけ見てライブに話す運用にも対応できる。要点からフル文は復元できないため、フル文を正とする）
- シーン見出しの尺・字数は見積り（トーク字数 ÷ 250 字/分。日本語ナレーションの標準 300 字/分に操作の間を織り込んだ実効値）

## 執筆規範（本文 → 話し言葉への変換）

1. **短文にし、文長に変化をつける**。書き言葉の長い複文は区切る。「〜であることが分かります」の型を繰り返さない
2. **会話調・二人称**で話す（「〜してみましょう」「あなたのエディタでは〜」）。本文の敬体を崩しすぎない
3. **画面に見えている文・コードをそのまま読み上げない**（音声と画面の重複は学習を妨げる）。コードは指し示しながら「意味」を話す（「この2つ目の引数が、実際に実行される処理です」）
4. **本文に無い新しい説明を足さない**（本文が正。足したくなった内容は本文の不足なので /write で本文へ入れてから台本に反映する）
5. **音読して確認する**。読みにくい漢語は開く（「〜を実施します」→「〜をやっていきます」）。固有名詞・英語の読みを収録メモに添えてよい

## 尺と分割

- **1本 = 1学習目標**。6 分未満を目標、9 分を上限とする（超えるなら分割。視聴データの裏付けあり）
- 分割境界は本文の `##` 見出し・Step 境界に合わせる（視聴者は Step 境界でポーズ・再視聴するため、動画の切れ目と教材の節目を一致させる）
- 目安: 本文 4,000 字の Section はトーク 2,000〜3,000 字＝ 2〜3 本になることが多い

## シーン設計（シーン = リテイク単位）

- **1 シーン = 1 画面状態 = トーク 150〜300 字**（実効 250 字/分で約 40〜70 秒）。シーンの切れ目が、録り直しの単位・編集点・字幕ブロックを兼ねる
- シーン番号は動画ごとに 1 から振り直す（素材命名は `-v2` などの動画番号で区別する）
- 言い間違えたらポーズで誤魔化さず、**そのシーンの頭から録り直す**（クリーンな素材が編集を最速にする）
- 画面状態が変わるところ（別ファイルを開く・ブラウザに切り替える）で必ずシーンを切る

## ワイプ指示

- 既定は **通常**（右下・重要な UI を覆わない位置。画面側にワイプ用の余白を確保する）
- **新出の図・コードを注視させるシーンは 縮小 / 非表示** を指示する（講師映像は視線を引きつけ、新しい内容への注視を遅らせるため）
- 導入・まとめは **顔全画面** も使える。カメラ目線・普段の話し方でよい（スタジオ品質より、自席の等身大の語りの方が視聴されるという実証がある）

## 実演の見せ方（本文の位置ルールとの対応）

- 実践見出し配下（🏃 打つコード）: **本質の数行だけライブで打つ**。定型・長いコードは準備済みファイルやスニペット貼り付けにする（打つ姿を見せる価値がある行に絞る）
- 読む例（📖）: 完成形を静的に表示し、指し示しながら話す（ライブで打たない）
- デモの初期状態は Git ブランチ / タグで固定し、テイクごとにリセットできるようにする。全コマンドは収録前に一度実走して確認する（本文の verified スタンプがあるコマンド列はその環境を再現する）

## 収録前チェックリスト（収録メモと併用）

- [ ] 通知 OFF・無関係なウィンドウ / アイコン / ブックマークバーを整理した
- [ ] エディタ・ターミナルのフォントを拡大した（1080p で読める大きさ）
- [ ] 解像度 1080p・16:9、ワイプの位置とサイズをテスト録画で確認した
- [ ] 操作は普段の半分の速度で行う（カーソルの動きを追わせる）
- [ ] 個人情報・トークン・実在の組織名が画面に出ないことを確認した
- [ ] デモ初期状態（収録メモの記載）を再現し、スナップショットを取った
- [ ] マイク音量をテスト録画で確認した

## 字幕・トランスクリプト

- トーク欄（フル文）がそのまま字幕原稿・トランスクリプトになる（説明は映像ではなくナレーションに載せておくのがアクセシビリティ上も最善）
- 字幕化する場合の目安: 1 行 13〜16 文字・最大 2 行（編集側の規範。台本側での対応は不要）
