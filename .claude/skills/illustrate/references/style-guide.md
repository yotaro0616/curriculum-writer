# プロンプトスタイルガイド

教材の概念図のスタイル基準とプロンプト構成ルール。**genai（Gemini / OpenAI）の生成プロンプトにも、Claude Design への作図依頼文にも、同じ配色・トーン・テンプレートを共通で使う**（経路が混在しても図が 1 セットに見える）。

## 基本ルール

| 項目 | ルール |
|------|--------|
| 言語 | **ラベル・キーワードは日本語** で指定する。英語の専門用語（技術教材の例: API, REST）はそのまま使用可 |
| スタイル | フラットなインフォグラフィック／ベクターイラスト風を基調にする。写実表現・ぼかし・過度なグラデーションは避ける |
| 立体感 | **アイソメトリック（斜め上から見下ろす）視点で立体感を出す**。箱・建物・道具などのオブジェクトに厚みを持たせ、平板な「ペラ１」の絵にしない |
| 影 | **オブジェクト真下の単色フラット影のみ**可（立体感の補強）。ぼかし影・アンビエントな陰影・背景に落ちる影は避ける（背景が荒れる原因になる） |
| 背景 | 白背景（#FFFFFF）。単色で塗りつぶし、テクスチャ・しみ・もや・かすれを描かない |
| 配色 | 青系（#3B82F6）とオレンジ系（#F97316）をアクセントカラーとする。対比図では左右で色を分ける |
| 線画 | アウトライン付きのクリーンな線画。手書き風にしない |
| 情報量 | 1枚に盛り込む概念は1つ。要素は5〜8個以内に抑える |
| 文字 | 大きく読みやすいラベルのみ。長文は入れない |

💡 配色は /pilot の「ブランドの一元設定」で教材のキーカラーに合わせて調整してよい（その場合はこのファイルの配色を更新して正とする）。

> ⚠️ **文字アーティファクトに注意**（genai）: Gemini は日本語ラベルを概ね正しく描くが、ラベルが多い・指示が曖昧だと、無関係な英単語（例: "CLICK"）やタイトル見出し、崩れた文字が混入することがある。生成後は必ず目視で確認し、混入したらラベルを減らす・「指定外の文字やタイトルは入れない」と明記する等で再生成する。**OpenAI（GPT Image）は日本語ラベルの再現が正確で、この症状が出にくい**（`gpt-image-2` で検証・2026-06 時点）。

> ⚠️ **背景のしみ・もや（4K アーティファクト）に注意**（genai）: 白背景の広い領域に、横スジ状の薄いしみ・もや・かすれが出ることがある。これは **Gemini の 4K アップスケーラ固有** の症状で、プロンプトで「背景は純白・テクスチャなし」と指示しても 4K では消えないことが多い。その場合は **`--resolution 2k` で生成し直す**（2K でも Web / GitHub Pages 表示には十分な解像度）か、**OpenAI（GPT Image）に切り替える**（OpenAI ではこの症状は基本的に発生しない）。

> 💡 **プロバイダ別のサイズ**（genai）: プロンプト末尾の「16:9 横長レイアウト」は両プロバイダの既定（Gemini = 4K / 16:9、OpenAI `gpt-image-2` = `1792x1008` / 16:9）に対応する。OpenAI では比率は API の `--size` で決まり、プロンプトの比率指定より優先されるため、テンプレートの文言はそのまま使ってよい（サイズ制約の詳細は `generate-image.js --help` を正とする）。

## プロンプト構成テンプレート

```
[画像の種類]を作成してください。

【内容】
- [何を描くか。比喩を使う場合はその対応関係を具体的に説明する]

【スタイル】
- フラットなインフォグラフィック／ベクター風を基調に、アイソメトリック（斜め上視点）で立体感を出す（オブジェクトに厚みを持たせる）
- 影はオブジェクト真下の単色フラット影のみ。ぼかし影・グラデーションは使わない
- 背景は #FFFFFF の単色。テクスチャ・しみ・もや・かすれを描かない
- 青（#3B82F6）とオレンジ（#F97316）のアクセントカラー、クリーンな線画、ラベルは日本語
- タイトルや無関係な英単語など、指定外の文字は入れない
- 16:9 横長レイアウト
```

**ポイント**: 【内容】セクションは具体的に書く。「○○の図」と曖昧に書くのではなく、「中央に△△、左側に□□、右側に◇◇、それらを矢印でつなぐ」のように、構図を明確に指定する。

Claude Design への作図依頼文では、このテンプレートの【スタイル】をそのまま使い、命名などの追加項目を `claude-design-guide.md` の依頼テンプレートで補う。

## 画像の種類別ガイド

criteria.md の 3 つの構図に対応する。排他的ではなく、1 枚が複数を兼ねてよい。

### 比喩図（メンタルモデル）

抽象概念を日常の物・場面（工場・倉庫・建物・道具等）に置き換え、「どういう感覚で捉えればいいか」を伝える。🧠（[人格名]の語り）の比喩を絵にするのに最適。

- 中心に主概念を配置し、周囲に関連要素を配置する
- 主題の用語と日常の比喩を **併記** する（技術教材の例: 「倉庫番 = ○○コンテナ」）
- 対応関係が一目でわかる構図にする

### 対比図（Before/After）

技術の「なぜ必要か」や思考の転換を、左右の対比で視覚的に伝える。

- 左右に分割し、左に旧/課題、右に新/解決を配置する
- 矢印で転換を示す
- 左右で配色を分ける（左: グレー寄り、右: 青/オレンジのアクセント）

### 鳥瞰図（地図）

複雑なシステムの全体像を「地図」として 1 枚に収める。Mermaid の箱図では伝わりにくい「全体の形・配置の感覚」を担う。

- アイソメトリック（斜め上から見下ろす）視点で、街・施設の地図のように描く
- 全体の「形」を把握できる程度に簡略化する
- **各要素を日常の物に見立て、正式名と比喩ラベルを併記する**（技術教材の例: DB = 地下金庫のある銀行、外部サービス = 取引先の建物、ロードバランサ = 交通整理員）
