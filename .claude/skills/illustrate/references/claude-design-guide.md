# Claude Design 作図ガイド

Claude Design（claude.ai/design）で教材の概念図を作るためのガイド。`/illustrate` の plan が出す図リスト（作図依頼リスト）を入力に、作図 → zip 書き出し → `/design-ingest` 取り込みまでの手順とコツをまとめる。

スタイル（配色・トーン・構図の型）は `style-guide.md` を正とする。genai 経路の生成プロンプトと同じテンプレート・配色を依頼文に使うことで、経路が混在しても図が 1 セットに見える。

## 前提

- **claude.ai アカウントで Design 機能が使えること**: ブラウザで claude.ai/design を開けるか確認する（プラン・ロールアウト状況により利用できない場合がある）
- **zip 書き出しの場所**: 作図した図はプロジェクト画面の書き出し（エクスポート）操作で zip として `~/Downloads` に保存できる。取り込み側の前提（Node.js / unzip）は `/design-ingest` の SKILL.md を参照

## 全体の流れ

1. `/illustrate plan <スコープ>` で図リスト（アンカー / 中心概念 / 構図 / 画像名）を確定する
2. claude.ai/design のプロジェクトで、1 図ずつ依頼文（下記テンプレート）を渡して作図する
3. 各図のファイル名を `<section番号>-<concept-slug>` に設定する（`/design-ingest` の自動対応の鍵）
4. プロジェクトを zip で書き出す（`~/Downloads` に保存される）
5. `/design-ingest` を実行する（配置・タグ挿入・zip 退避まで自動）

💡 教材専用のプロジェクトを 1 つ作り、全 Part の図をそこで管理する。プロジェクト内で図を `assets/diagrams/output/<name>.png` の配置にしておくと、書き出した zip がリポジトリと同じパス構造になり取り込みが確実になる（ファイル名が `<section番号>-` 始まりであれば、フラットな配置でも取り込める）。

## 1. 作図依頼テンプレート

plan の図リスト 1 行を、次のテンプレートに展開して依頼する。【スタイル】は `style-guide.md` の「基本ルール」と同じ内容（/pilot で教材のキーカラーを変えている場合はそちらに合わせる）。この依頼文は `assets/diagrams/prompts/<name>.md` にも保存する（`criteria.md`「5. 画像の規範」）。

```
教材の概念図を 1 枚作ってください。

【図の名前】<section番号>-<concept-slug>（このファイル名で保存）
【中心概念】[plan の「中心概念」。1 枚 1 概念]
【構図】[比喩図 / 対比図 / 鳥瞰図。配置まで具体的に。例: 左に旧方式（グレー基調）、右に新方式（青基調）、中央に転換の矢印]
【ラベル】[入れる日本語ラベルを列挙する（5〜8 個以内）。指定外の文字・タイトルは入れない]
【スタイル】
- フラットなインフォグラフィック／ベクター風。アイソメトリック（斜め上視点）で立体感を出す
- 背景は #FFFFFF の単色。影はオブジェクト真下の単色フラット影のみ
- アクセントカラーは青（#3B82F6）とオレンジ（#F97316）。クリーンな線画
- 16:9 横長レイアウト
```

構図・ラベルの決め方（1 枚 1 概念・要素 5〜8 個・🧠 の比喩に呼応させる）は `criteria.md` に従う。

## 2. 複数案を出して比較する

- 方向性が固まっていない最初の 1 図は、**「構図を変えて 3 案作ってください」** のように複数案を依頼して比較する。以降の図は選んだ案のスタイルをベースに揃える
- 比較の観点: ラベルの読みやすさ / 要素数（多すぎないか）/ 🧠 の比喩との呼応 / 縮小表示（教材ページの幅）での視認性
- ⚠️ 選ばなかった案はプロジェクトから削除する（または `<section番号>-` で始まらない名前に変える）。`/design-ingest` は Section 番号始まりの画像をすべて取り込むため、残したまま書き出すと没案まで配置される

## 3. 部分修正の依頼

全体を作り直さずに一部だけ直せるのが Claude Design の利点。修正は差分で依頼する。

- 直したい要素を選択（または名指し）して、**「〜だけ変えて、他は維持」** と依頼する
  - 例: 「ラベル『DIコンテナ』を『DI コンテナ』に変えて。他は維持」
  - 例: 「右側の建物だけ青系にして。左のグレーはそのまま」
- 文言・配色・1 オブジェクトの差し替えは部分修正で対応し、構図ごと変える場合（左右対比 → 鳥瞰など）は作り直しとして依頼する（`criteria.md`「5. 画像の規範」の改版 `-v2` に当たる）
- 修正後は同名で上書き保存すれば、`/design-ingest` が `updated` として画像だけ差し替える（タグ変更不要）

## 4. デザインシステムで統一感を出す

教材全体（Part をまたぐ複数枚）で図を 1 セットに見せるために、Claude Design のデザインシステム（プロジェクト共通のスタイル定義）を使う。

- 最初の図で方向性が決まったら、**その配色・線・影・ラベルの書体をデザインシステムに登録する**（「この図のスタイルをデザインシステムにまとめて」と依頼できる）。初期値には `style-guide.md` の基本ルール（配色・トーン）を渡す
- 以降の作図では「デザインシステムに従って」と一言添える。依頼文の【スタイル】を毎回詳述しなくてもブレなくなる
- 改版・追加もデザインシステムの上で行うと、作図時期をまたいでも一貫性が保たれる（`criteria.md`「Part 内でスタイル統一」の実現手段）

## 5. zip 書き出しと取り込み

1. **ファイル名を最終確認する**: すべての図が `<section番号>-<concept-slug>`（例: 3層 `2-1-4-http-request`）になっているか。スラッグは数字始まりを避ける
2. **プロジェクトを zip で書き出す**: 書き出した zip は `~/Downloads` に落ちる（保存先を変えた場合は `/design-ingest` に `--zip <path>` で渡す）
3. **`/design-ingest` を実行する**: `~/Downloads` から zip を自動検出し、`assets/diagrams/output/` への配置・Section へのタグ挿入・zip の退避（`~/Downloads/_design_ingested/`）まで行う。まず `--dry-run` で検出結果を確認すると確実
4. 取り込み結果（new / updated / unchanged・タグ挿入した Section・Section 未対応）は `/design-ingest` が報告する

書き出しは PNG が基本（`/design-ingest` は png / jpg / svg を取り込める）。
