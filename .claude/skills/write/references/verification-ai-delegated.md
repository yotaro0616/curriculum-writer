# 検証モデル: ai-delegated（AI 委任型ハンズオン）

`config.verification_model: ai-delegated` の教材が使う執筆リファレンス。学習者が AI（Claude Code 等）に開発・作業を委任する教材では、writing.md「コードはコピペでビルド / 実行が通る形にする」を以下で読み替える（「足場」「動作確認」「裏取り」の節は共通で有効）。/write・/review は該当教材を扱う前に本ファイルを読む。

**AI 委任型ハンズオンの書き方**:

- **固定層と流動層を分ける**: 固定層（学習者が打つコマンド・貼り付けるプロンプト・UI 操作）は正確にそのまま書き、再現を保証する。流動層（AI が生成するコード・対話の細部）は「形の一例です。あなたのものは違ってかまいません」と明示した場合にのみ掲載する
- **ゴールは観察できる達成状態**: 各 Step の完了は「テストが通る」「画面に○○が表示される」のような観察可能な状態で定義し、生成コードの一致では検証しない
- **症状ベースの先回り**: 詰まりは「〜というエラー・状態になったら」と症状から書く（AI の出力経路は一定でないため、操作手順ベースの先回りは効きにくい）
- **AI 生成物を後続 Section で当てにしない**: 後続 Section が前提にできるのは固定層の成果物だけ
- **過程の成果物を再現性の背骨にする**: 仕様書・チェックリスト・タスクリストなど、AI とのやり取りで生まれる中間成果物を各 Step の検証ゲートに使う
- **模範プロンプトの見せ方**: 型（役割・文脈・指示・制約・出力形式）を踏まえた自然文で書き、「仮説:」「完成条件:」のような内部ラベルをそのまま渡す形にしない。貼り付け用プロンプトは要約せず text コードブロックで実文を載せる
- **検証（/review・handson-verifier）**: コマンドの正確性・状態の追跡は固定層のみを対象にし、達成判定は観察できる達成状態で行う。流動層に「一例」の明示があるかを確認する
