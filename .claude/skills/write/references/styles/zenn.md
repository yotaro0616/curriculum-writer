# 様式リファレンス: zenn（Zenn 記法）

`config.style: zenn` の教材が使う読み替え表と記法カタログ。**構造・順序・執筆ルールは writing.md と共通**で、コールアウト・コード・画像を Zenn の Markdown 記法に置き換える。**本文中の絵文字は使わない**（枠見出しは plain 様式と同一）。

> 出典: [Zenn 公式 Markdown 記法一覧](https://zenn.dev/zenn/articles/markdown-guide)（採用時に最新を確認すること）
>
> ⚠️ このファイルは fw-sync の更新対象（カテゴリ A）。プロジェクト固有の語の調整はここを直接編集せず、writing.md 側に上書きとして書く（カテゴリ B で保護される）。枠見出しの対応表は plain / admonition / zenn の3ファイルに同型で存在し、変更時は3枚 + writing.md のテンプレートを同期する。

⚠️ **適用範囲とレンダラ依存**: この様式の適用先は「**相対パスの画像を解決できる** zenn-markdown-html 互換レンダラ（LMS 埋め込み等）」に限る。`:::message` 等の Zenn 独自記法は GitHub 直読み・MkDocs では素のテキストになる。また **Zenn 本体（GitHub 連携）への公開は本様式単独では非対応**: Zenn 本体は画像がリポジトリ直下 `/images` への絶対パス参照のみ（`../` 不可・3MB・png/jpg/jpeg/gif/webp 限定）で、FW の `assets/` 相対パス規約と非互換のため、公開には画像パス変換層（exporter）が別途必要になる。公開先のレンダラと**画像の配信方式**を確認してからこの様式を選ぶこと（/research Phase 0 の公開方式で確認し、/pilot の公開形式プレビューで実描画を検証する）。

## 枠見出しの対応表

plain 様式と同一（絵文字なしのテキスト見出し）:

| emoji 様式 | zenn 様式 |
|---|---|
| `## 🎯 このセクションで学ぶこと` | `## このセクションで学ぶこと` |
| `## ✨ まとめ` | `## まとめ` |
| `## 🏃 実践: [タイトル]` | `## 実践: [タイトル]` |
| `### 🏃 Step N: [タイトル]` | `### Step N: [タイトル]` |
| `## 🏃 やってみよう: [タイトル]` | `## やってみよう: [タイトル]` |
| `## 📌 [作業名]前の確認` | `## [作業名]前の確認` |
| `## ✅ 完成チェックリスト` | `## 完成チェックリスト` |
| `### 🧠 [人格名]はこう考える` | `### [人格名]はこう考える` |
| `📖 **この Chapter の進め方**: ...` | `**この Chapter の進め方**: ...` |

**位置ルール（実行コードの目印）の読み替え**: 「打つのは 🏃 配下だけ」は「打つのは**実践見出し**（`## 実践:` / `### Step N:` / `## やってみよう:`）の配下だけ」と読む。

## コールアウトの対応表

| emoji 様式 | zenn 様式 | 使い所 |
|---|---|---|
| 💡 TIP・補足 / 📝 ノート・前提知識 / 🔑 キーポイント | `:::message` 〜 `:::`（1行目を `**ヒント**:` / `**補足**:` / `**前提知識**:` / `**ポイント**:` の太字ラベルで始める） | 補足・前提・キーポイント |
| ⚠️ 注意・よくあるエラー | `:::message alert` 〜 `:::` | 破壊的操作・詰まりやすいエラー |
| `<details>`（長いコードの折りたたみ） | `:::details タイトル` 〜 `:::` | 長いログ・コード全文の退避。本筋は折り畳まない |
| やってみよう末尾の ✅ 確認 | `**確認**: ...`（記法なし） | |

- **よくあるエラーの blockquote テンプレート**（`> ⚠️ **よくあるエラー**: ...`）は、`:::message alert` の中に構造ごと収める（1行目 `**よくあるエラー**: [概要]` → エラーメッセージのコードブロック → **原因** / **対処法**）
- **役割行（weave 教材のみ）**: `**入力**:` / `**実行**:` / `**読む例**:`（絵文字なし。plain 様式と同形）
- message / details のネストは外側を `::::`（コロン4つ）にする
- コールアウトは 1 Section 3〜4個まで・同種の連続配置をしない（他様式と同じ運用）
- **OS 差の書き分け**: Zenn にはコンテンツタブが無い。短い差はインライン併記、長い差は見出し分割または `:::details macOS` / `:::details Windows` の2連で書き分ける

## コードの見せ方（writing.md の読み替え）

- **ファイルパスの明示**は、コメント行ではなく Zenn のファイル名付きコードブロックで行う: ` ```php:app/Http/Controllers/PostController.php `（writing.md「コードブロック上部にファイルパスをコメントで明示」の代替。コピペ時にコメントが混入しない利点がある）
- **diff の限定解禁**: 読んで理解する変更説明に限り ` ```diff php ` を使ってよい。**学習者が打つ・貼るコード（実践見出し配下の実行用ブロック）には使わない**（`+` `-` 記号がコピペを壊すため。writing.md の「diff 表示は使わない」はこの範囲で緩和される）
- 言語タグ必須・非コードは `text`、Mermaid は ` ```mermaid `（他様式と共通）

## 画像

- `![alt](パス)` の直後の行に `*キャプション*` を置ける（Zenn がキャプションとして描画する）
- 横幅指定が必要な場合は `![alt](パス =250x)`（⚠️ Zenn 専用。CommonMark 系レンダラでは**画像ごと描画されなくなる**ため、Zenn 系レンダラ以外に流用しない）
- alt は必須（内容を説明する日本語）

## その他の Zenn 記法と制約（使い所の基準）

| 記法 | 書式 | 教材での使い所 |
|---|---|---|
| 脚注 | `本文[^1]` + `[^1]: 内容`（インライン式 `^[内容]` は Zenn 専用） | 本筋から外れる補足・免責。連発しない |
| 数式 | `$$ ... $$` / `$...$`（KaTeX）。**`$$` の前後は空行にする**（公式注記） | 必要時のみ |
| リンクカード | URL を単独行 | 主要な参照先の提示。出典リンクは文中リンクを基本にし、カードを乱用しない |
| YouTube / X 埋め込み | URL を単独行 | デモ動画等。必要時のみ |
| GitHub 埋め込み | ファイル URL 単独行（`#L1-L3` で行指定） | 実コードの参照（貼り直さず行指定で埋め込むと陳腐化しにくい） |
| Mermaid | ` ```mermaid `（**1ブロック 2000 字以内・チェイン `&` 10 以下**の公式制限） | 処理フロー・関係図（config.diagram_format と整合） |
| 区切り線 | `---` | テンプレートの区切り（他様式と共通） |

**HTML の制約**: Zenn 本文で使える HTML は `<br>` と HTML コメントのみで、**コメントは1行のみ対応**（複数行コメント不可）。`<details>` / `<img>` / `<kbd>` 等は使えない。📸 撮影指示・verified / captured スタンプのコメントは必ず1行で書く。

## Zenn 本体へ公開する場合の付帯仕様

公開先が Zenn（本）の場合のみ関係する。LMS 等が Zenn 互換レンダラを使うだけなら不要。

- slug: `a-z0-9-_` の 12〜50字・**一度作成したら変更不可**（本のチャプターは 1〜50字）
- 本は `books/<slug>/` + `config.yaml`（title / summary / topics / published / price / chapters。chapters 配列が並び順の単一の正）
- **published: true への切り替えは人間のみが行う**（Zenn 規約の自動生成投稿対策・公開前の人間検証）

## 機械チェック（lint）の挙動

- 絵文字は**全面禁止**（`emoji-forbidden` 🔴。HTML コメント内の 📸 撮影指示・verified スタンプは検査対象外）
- `container-unclosed`: `:::message` / `:::details` の閉じ `:::` が無い場合 🔴（ページ全体の描画が壊れるため）
- Section の必須構造は `## このセクションで学ぶこと` / `## まとめ` の見出しで判定する（🟡）
- broken-bold・sentence-bold・dash-char・code-fence-language・absolute-path は全様式共通
