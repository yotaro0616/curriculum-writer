# 様式リファレンス: plain（絵文字なしプレーン）

`config.style: plain` の教材が使う読み替え表。**構造・順序・執筆ルールは writing.md と共通**で、枠・コールアウトの見た目だけをプレーンな Markdown に置き換える。絵文字を一切使わないため、生成 AI 特有の装飾感を出したくない教材・レンダラを選ばない配布（LMS 貼り付け・PDF 化等）に向く。

> ⚠️ このファイルは fw-sync の更新対象（カテゴリ A）。プロジェクト固有の語の調整はここを直接編集せず、writing.md 側に上書きとして書く（カテゴリ B で保護される）。枠見出しの対応表は plain / admonition / zenn の3ファイルに同型で存在し、変更時は3枚 + writing.md のテンプレートを同期する。

## 枠見出しの対応表

| emoji 様式 | plain 様式 |
|---|---|
| `## 🎯 このセクションで学ぶこと` | `## このセクションで学ぶこと` |
| `## ✨ まとめ` | `## まとめ` |
| `## 🏃 実践: [タイトル]` | `## 実践: [タイトル]` |
| `### 🏃 Step N: [タイトル]` | `### Step N: [タイトル]` |
| `## 🏃 やってみよう: [タイトル]` | `## やってみよう: [タイトル]` |
| `## 📌 [作業名]前の確認` | `## [作業名]前の確認` |
| `## ✅ 完成チェックリスト` | `## 完成チェックリスト` |
| `### 🧠 [人格名]はこう考える` | `### [人格名]はこう考える` |
| `📖 **この Chapter の進め方**: ...` | `**この Chapter の進め方**: ...` |

**位置ルール（実行コードの目印）の読み替え**: 「打つのは 🏃 配下だけ」は「打つのは**実践見出し**（`## 実践:` / `### Step N:` / `## やってみよう:`）の配下だけ」と読む。見出しはこの3形を正確に使い、類似の言い換え（「動かしてみる」等）を実践見出しに使わない（学習者とレビュー双方の判定基準になるため）。

## コールアウトの対応表

行頭の太字ラベル＋コロンで示す。単文はインライン、複数文・重要度が高いものは blockquote にする。

| emoji 様式 | plain 様式 |
|---|---|
| `💡 ...`（TIP・補足） | `> **ヒント**: ...` |
| `📝 ...`（ノート・定義） | `> **補足**: ...` |
| `📝 **前提知識**: ...` | `> **前提知識**: ...` |
| `🔑 ...`（重要概念） | `> **ポイント**: ...` |
| `⚠️ **注意**: ...` | `> **注意**: ...` |
| やってみよう末尾の `✅ ...`（確認） | `**確認**: ...` |
| ✅ チェックリストの各項目 | `- [ ] ...`（チェックボックス） |

- よくあるエラーの blockquote テンプレート（`> ⚠️ **よくあるエラー**: ...`）は先頭を `> **よくあるエラー**: ...` に読み替える（**原因** / **対処法** の構造は共通）
- **役割行（weave 教材のみ）**: `🏃 **入力**:` / `🏃 **実行**:` / `📖 **読む例**:` は絵文字を落として `**入力**:` / `**実行**:` / `**読む例**:` と書く
- **折りたたみ**: 既定では使わない（長いコードは「付録」「解答」等の見出し分割で対応する）。公開先が GitHub 系レンダラと確定している場合のみ `<details>` を使ってよい（PDF・一部 LMS では折りたたまれず全展開になるため）
- コールアウトは 1 Section 3〜4個まで・同種の連続配置をしない（admonition 様式と同じ運用）

## 機械チェック（lint）の挙動

- 絵文字は**全面禁止**（`emoji-forbidden` 🔴。HTML コメント内の 📸 撮影指示・verified スタンプは検査対象外）
- Section の必須構造は `## このセクションで学ぶこと` / `## まとめ` の見出しで判定する（🟡）
- broken-bold・sentence-bold・dash-char・code-fence-language・absolute-path は全様式共通

## 執筆時の注意

- 太字ラベル（`**ヒント**:` 等）は textlint の強調パターン検査で許可済みの語を使う（ヒント / 補足 / 前提知識 / ポイント / 注意 / 確認 / よくあるエラー / 原因 / 対処法 / この Chapter の進め方）。新しいラベルを増やす場合は `.textlintrc.json` の allows も更新する
- 絵文字が無いぶん、見出し・ラベルの**言葉の規律**が唯一の視覚シグナルになる。対応表以外の枠を発明しない
