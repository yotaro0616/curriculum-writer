# 学習モデル: weave（織り込み型）

`config.section_model: weave` の教材が使う執筆リファレンス。「短い説明 → 打つ → 確認」の小さいループが本文の主役になるタイピング中心のチュートリアル教材（完全初心者向け等）の規範を定義する。**/write・/review・/outline は weave 教材を扱う前に必ず本ファイルを読む**（サブエージェントにもパスで渡す）。writing.md の共通ルールに対し、本ファイルの読み替えが優先する。

> 設計根拠: 例と練習の 1:1 交互配置（Trafton & Reiser）/ 極小粒・即実行・微修正の写経（Edwards 2020）/ サブゴールラベル（Margulieux）/ PRIMM / Diátaxis tutorial 原則 / Codelabs・fCC・Laravel Bootcamp の構造。詳細は FW リポジトリの PR 記録を参照。

## 1. 種類の使い分け（weave での判定）

| 判定 | 種類 |
|---|---|
| 手を動かして学ぶ節（既定） | **混合（織り込み構成）** |
| 概念導入が長く（3段落超）、実践が分割不能な一塊（環境構築等） | 混合（二段構成）と注記 |
| 本当に読むだけの節（例: Web の仕組み） | 概念 |
| 既習の複数機能を束ねる統合実践（章末・部末） | ハンズオン |

- **概念 Section は Chapter あたり 0〜1 を目安**とし、超過する場合は OUTLINE の種類方針に理由を明記して可（配置は Chapter 内外を問わず2連続まで）
- 構成形（二段 / 織り込み）は /outline の骨子充填時に確定し、OUTLINE の種類フィールドに注記する（無印は織り込み）
- **tryit_timing は weave では N/A**（概念 Section が少なく「やってみよう」の置き場がほぼ無い。概念 Section に置く場合のみ B＝同一パスで書き、OUTLINE 付録「やってみよう表」は作らない）
- **verification_model は copypaste（決定的再現型）のみサポート**。weave × ai-delegated は未定義（/pilot で警告し、separate に変えるか copypaste にする）

## 2. Section 骨格（混合＝織り込み構成の専用開始アーク）

混合（織り込み）では config.arc_mode を適用しない（専用アーク。**概念・ハンズオン Section には選択済みの arc_mode をそのまま適用する**）。冒頭の読み物を圧縮し、最初の打鍵まで最短で到達させる。「概要」「なぜ〇〇を使うのか」「〇〇とは何か」の定型見出しは**置かない**（Why は完成イメージと導入文が兼ねる。深掘りは概念 Section へ）。

```markdown
# [セクション番号] セクションタイトル

<!-- 前提がある場合: 📝 **前提知識** 行 -->

## 🎯 このセクションで学ぶこと

- 学習目標1
- 学習目標2

- 目安時間: 約○分   ← 任意。置く場合はこの位置・この書式（箇条書き1行）に固定

**このセクションで作るもの**: [完成状態の1〜2文。なぜ作るかを兼ねる]

<!-- 📸 capture: ...（完成イメージ。画面に見える成果がある節のみ。無い節は実行結果の text ブロックで代替か省略） -->

### 🧠 [人格名]はこう考える   ← 頻度は config.persona_frequency に従う。位置はここ（冒頭ブロック末尾）に固定

> [語り]

---

## 📌 はじめる前の確認   ← 前の Section の状態を前提にする節のみ。チェックリスト形式

## [トピック見出し]        ← ここから説明と Step の織り込み

[説明 1〜3段落（この Step 群に必要な分だけ）]

### 🏃 Step 1: [サブゴール]

### 🏃 Step 2: [サブゴール]

## [次のトピック見出し]

### 🏃 Step 3: [サブゴール]   ← Step 番号は Section 内の通し連番（見出しをまたいでもリセットしない）

---

## ✅ 完成チェックリスト   ← 必須（最小2項目でよい。最終 Step の観察文の再掲で可）

## ✨ まとめ

- ポイント（2〜3行の箇条書き。想起型にするのは OUTLINE で接点指定された節のみ）

---

次のセクションでは、[次の内容への接続]。
```

- /illustrate の代表図アンカーは「冒頭ブロック（🧠 があればその直後・無ければ完成イメージの直後）・最初の `---` の直前」と読み替える
- 概念 Section・ハンズオン Section は writing.md の共通テンプレート（選択済み arc_mode）のまま書く（weave 骨格は混合＝織り込み構成専用）

## 3. 織り込み構成の境界規則（位置ルールの weave 詳細）

打つ / 読むの区別は「実践見出し + 役割行」の二重で示す。

1. **Step の支配範囲は次の見出し（### / ##）まで**。Step 配下に「読む例」を置かない。読む例は Step の外（`##` 説明ブロック）に置く
2. **Step 直前に、打鍵対象と同一・類似の読む例を置かない**（コードの逐行解説は打って動かした後に行う）
3. **役割行**: Step 配下のコードブロックの直前に、何をするかを1行で宣言する（lint `role-line-missing` が検査）:
   - `🏃 **入力**: \`routes/web.php\`（追記）` … エディタに打つ。対象パスと操作種別（新規作成 | 追記 | 置換 | 一部変更: アンカー）を必ず書く
   - `🏃 **実行**: プロジェクトルートで` … ターミナルで実行する。実行場所を必ず書く（1コマンド1ブロックは共通ルールどおり）
   - plain / admonition / zenn 様式では絵文字を落とし `**入力**:` / `**実行**:` とする
   - 入力の役割行が対象パスを示すため、**打たせるブロック内のファイルパスコメントは省略してよい**（学習者がコメントまで打つ混乱を避ける。読む例は共通ルールどおりコメントで示す）
4. **読む例の宣言**: 実践見出しの外に置くコードブロック（text / mermaid を除く）には、直前に `📖 **読む例**: [一言]` を置く（plain 系様式では `**読む例**:`。lint `read-example-missing` が検査）。読む例の直後に実行を促す文言を書かない
5. 出力例・失敗時分岐のコマンドなど「打たせない」補助ブロックは `text` タグまたは blockquote 内に置く（読む用の器。役割行は不要）
6. 学習者向けルールは**教材の最初の Section**（Chapter 1 冒頭の導入節）で1文宣言する: 「**入力** / **実行** のマークが付いたコードだけ手を動かします。**読む例** は読むだけです」（/outline 骨格設計時に当該節のゴールへ含める）

## 4. 執筆規範（Step の書き方）

1. **1 Step = 1つの観察可能な変化**。打鍵は数行〜十数行・数分以内。長いコードは追記 Step に分割し、まとめて全文を写させない
2. **Step 見出しはサブゴール**（「Step 3: URL と処理を対応づける」）。操作がそのままサブゴールである些末な Step（「文字色を変える」等）は操作名でよい
3. **説明は打つ直前に最小限**（1〜3段落）。理由付けは1〜2文で、深掘り・背景は概念 Section か 💡 に逃がす
4. **Step は観察文で締める**: コード・コマンドの直後に「〜が表示されます」の観察可能な結果を必ず書き、なぜそうなるかを1文添える
5. **失敗時分岐は絞る**: 「表示されない場合は〜」は初回操作・環境依存・非決定的な箇所にのみ付け、それ以外の定番の詰まりは Chapter 末尾の「つまずいたら」表（付録）に集約する（全 Step に定型分岐を付けない。⚠️ の書式は共通ルールどおり症状ベース）
6. **1点変えてみよう（任意）**: Step の末尾に「値・文言を1箇所だけ変えて再実行 → 観察」の微修正を促せる（構文の定着に最も効く。多用せず Chapter に数回）
7. **予測（任意）**: 実行の直前に `📝 **予測**: 実行すると何が表示されるか、考えてから進んでください。` を置ける（plain / admonition / zenn 様式では `**予測**:`。Part 前半の重要 Step に絞る）
8. **手順文は 1 Step 1 アクション**: 場所 → 操作の順（「`routes/web.php` に、次の3行を追加します」）で命令形に統一する
9. **GUI 操作の適用除外**: エディタでの新規ファイル作成・保存・ブラウザ再読み込みが主となる序盤（HTML/CSS 等）では、ファイル作成コマンド（mkdir / touch）の共通ルールを適用せず、場所 → 操作の命令文で書く。ターミナル系ルールの適用開始点は OUTLINE の Part 方針に明記する
10. **反復の緩和**: 重要概念は形を変えて2回まで再説明してよい（「同じ概念を繰り返さない」共通ルールの weave 限定緩和）
11. **足場外し**: Part 進行に応じてコード提示の完全度を下げる（全文提示 → 穴埋め・1点変更 → 要求仕様のみ）。方針は OUTLINE の Part 方針に書く

## 5. 状態契約と検証（weave での運用）

- ほぼ全 Section が状態を運ぶため、**終了状態フィールドは実質必須**（/outline 骨子充填時に記入し、次節の 📌 と突合する）
- **Chapter 先頭で状態を再構築できる手段を必ず用意する**（リセット手順 / 配布スナップショット / git tag のいずれか。OUTLINE 付録「ハンズオンの共通方針」に記録）。学習者の中断・再開点と、handson-verifier の検証起点を兼ねる
- handson-verifier・verified スタンプは **Chapter 単位の通し実行**を基本にしてよい（Section 単位で分割検証しない）
- ✨ まとめの想起型（確認問題 + 折りたたみ解答）は、OUTLINE で「接点」指定された節にのみ置く。解答の器は様式に従う（emoji: `<details>` / admonition: `??? note "解答"` / zenn: `:::details 解答` / **plain: 折りたたみ不可のため設問リストの直後に「解答」小見出しを分離して置く**。plain.md 参照）

## 6. ペーシング（/outline モード A の検査）

- **各 Chapter に非タイピング接点を最低1つ**計画する。接点 = 概念 Section、または「想起まとめを置く節」の指定（種類フィールドに `接点: 想起まとめ` と注記）。✨ の通常まとめは接点に数えない
- Chapter の目安時間合計（Section の目安時間の和）を出し、教材全体の想定学習時間（/define の学習時間モデル）と突合する

## 7. lint（weave 教材に関わる検査）

| ルール | 重要度 | 内容 |
|---|---|---|
| role-line-missing | 🟡 | Step 配下のコードブロックに役割行が無い（**weave のみ**） |
| read-example-missing | 🟡 | 実践見出し外のコードブロックに読む例宣言が無い（**weave のみ**） |
| practice-heading-form | 🔴 | 実践見出しの正規形違反（参考: 全様式・全モデル共通。正規形の単一ソースは lint の PRACTICE_* 定数） |
| step-numbering | 🟡 | Step 通し連番の飛び・重複（参考: 全様式・全モデル共通） |
