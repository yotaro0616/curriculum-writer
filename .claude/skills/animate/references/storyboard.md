# ストーリーボード仕様と台本の執筆ルール

ストーリーボードは動画の **単一の真実**（差分管理する設計図）。`video/data/<sectionId>.storyboard.json` に置く。
TTS スクリプトがこれを読み、音声と実測尺を埋めた `<sectionId>.props.json` を生成する（props.json は成果物なので手で編集しない。ただし実測尺を含むためコミットはする）。

動画の役割（要約ではなく Section の主たる学習路）と尺・シーン数の基準は `criteria.md` を参照する。本ファイルは JSON の形式と台本の書き方を定める。書き終えたら `node scripts/lint-storyboard.mjs <sectionId>` で機械検証してから TTS に進む。

## トップレベル

```json
{
  "sectionId": "1-2",
  "sectionLabel": "Part 1 基礎編 / Chapter 1",
  "title": "モデルの基礎",
  "scenes": [ ... ]
}
```

- `sectionId` は教材のセクション番号（OUTLINE の階層に応じた連番。例 `1-2`・`2-1-3`）。音声フォルダ名・mp4 名・配信 URL に使う
- `sectionLabel` は title シーンのラベル（ピル）に出る（`Part X タイトル / Chapter Y` 形式）。画面右上のセクションチップは `sectionId`＋`title` から自動で組まれ、sectionLabel は使われない

## シーン共通フィールド

| フィールド | 必須 | 内容 |
|---|---|---|
| `id` | ✅ | シーン識別子（kebab-case。音声ファイル名や修正指示に使う） |
| `type` | ✅ | シーン型（下記カタログ） |
| `heading` | 任意 | 画面左上の見出し（Section の `##` 見出しに対応させる）。title には付けない。焼き込みタイトルの figure では省く（criteria.md 5） |
| `narration` | ✅ | 字幕に表示する原稿（漢字・英字表記のまま） |
| `reading` | 任意 | 読み上げを個別調整したい時だけ。通常は **書かず** narration から自動生成する（下記「reading」参照） |

`audioSrc` / `audioFrames` / `totalFrames` は TTS スクリプトが埋めるので書かない。

## シーン型カタログ

- **title**: `sectionNo` / `title` / `subtitle`（導入の問いかけ 1 文）
- **codeCompare**: `left` / `right` の 2 ペイン。各ペインは **IDE ウィンドウ風**（信号機ドット＋ファイル名タブ＋行番号＋VSCode 風シンタックスハイライト、`src/highlight.ts` が自動で色付け）で描画される。フィールド: `file`（タブのファイル名。例 `src/models/Task.php`。省略時は `label`）・`lines`（コード行）・`errorLine`（0 始まり。エラー演出）・`caption`（ペイン下の一言）。`rightAt`（0〜1）で右ペインの登場を **ナレーションが右の話に移る位置** に合わせる（既定 0.45）
  - コードは「読み解く対象」。長すぎる全文は載せず、要点の数行に絞る（コピペ用の全文は本文が担う）
- **terminal**: ターミナルウィンドウ（信号機ドット＋中央タイトル）で、入力 → 出力を上から順に実演する。`codeCompare` が IDE（コードを読む）なら、`terminal` はシェル／AI エージェント CLI（コマンドを打つ・AI に任せる）。フィールド: `windowTitle`・`prompt`（既定の先頭プロンプト）・`revealAt`（各ステップの開始位置 0〜1 の配列。省略時は音声尺へ自動配分）・`lines`。`lines` の各要素は次のいずれか:
  - シェル: `{cmd, note?, prompt?}`（入力。タイピング＋右端に `# note`。`prompt` で行ごとに上書き＝`cd` 後の現在地表示など。`cmd: ""` は入力待ち＝プロンプト＋カーソル）／`{out}`（出力。フェード）／`{comment}`（`# 注釈`）
  - AI エージェントのセッション（Claude Code 等）: `{user}`（ユーザー発話＝`>`）／`{claude}`（応答＝アクセント色の `⏺`）／`{tool, result?}`（ツール実行＝緑の `⏺` ＋ `⎿ 結果`）／`{approve, options?}`（承認ゲート＝アクセント枠の確認ボックス。実行してよいかを問う）
  - ステップ（入力／発話／ツール／承認の各まとまり）はナレーションに合わせて段階表示される（全部を冒頭で出さない）。細部は本物に寄せすぎず、ナレーションが指す要点が伝わればよい。CLI 全般、AI エージェントの起動・操作・承認の実演に使う（サンプル: `video/data/_demo.props.json` の terminal シーン）
- **terminalCompare**: ターミナルを**左右2ペイン**並べ、指示の良し悪しと **出力の差** を対比する。`left` / `right` は各 `{windowTitle?, lines, caption?, good?}`（`lines` に使えるのは `{user}`／`{claude}`／`{comment}`／`{out}` の4種のみ。シェル行 `{cmd}`・ツール実行 `{tool}`・承認 `{approve}` は terminal シーン専用で、lint が検出する）。`good: true` を付けたペインは枠と caption がアクセント色で強調される（良い側）。`rightAt`（0〜1）で右ペインが動き出す位置をナレーションに合わせる。各ペインは行をナレーション尺に均等配分して1行ずつ出す。用途: 丸投げ↔具体的な指示の比較、出力の質の差を見せる（右に良い指示と良い出力、左に丸投げと浅い出力）
- **keypoint**: `cards`（2 枚。`title` と `body`）。二項対立・定義の対比用（1 枚目がアクセント色、2 枚目が無彩色の濃スレート）。`body` は `\n` で改行でき、要素を1行ずつ並べると構造的で読みやすい（長い1文の自動折り返しは避ける）。`revealAt`（各カードの登場比、例 `[0.05, 0.45]`）で **各概念にナレーションが触れる位置** に合わせる
- **figure**: `src`（`figures/<name>.jpg`。事前に `assets/diagrams/output/` から `video/public/figures/` へ cp する）・`alt`。/illustrate の白背景の概念図を額装して見せる
- **flow**: `steps`（`label`・`sub`・`emphasis`）+ 任意の `fanout`（分岐先チップ。各要素は **`{ "label": "..." }` のオブジェクト**。文字列の配列にすると空箱で描画される）+ 任意の `tagline`（締めの標語）。`emphasis: true` のステップは強調される。矢印は無彩色
  - **タイミング**: `revealAt`（ステップごとの 0〜1 配列）/ `fanoutAt`（fanout の登場。数値=その位置から少しずつ／**配列=チップごとに位置指定**）。**fanout が項目の列挙（「一つ目は〜、二つ目は〜」）なら、`fanoutAt` を配列にして各項目をナレーションで言う瞬間に1枚ずつ出す**（まとめて出すと違和感。例: 3項目を 0.18 / 0.38 / 0.53 で割り当てる）。fanout はチップが大きめのカードで出るので、項目名は短く（2〜6字程度）
- **nest**: `layers`（**内側 → 外側**の順に 3 つまで。`label`・`desc`）+ 任意の `revealAt`（**layers と同じ内側→外側の並び**で各層の登場位置を 0〜1 で指定。省略時は外側＝容れ物から自動。ナレーションで各層を言う順に合わせるときに使う）+ 任意の `formula`（例: `パッケージ ⊃ モジュール`）
- **outro**: `points`（まとめ 4 点以内。Section の ✨ に対応）+ `next`（次セクション番号とタイトル）

### 記号の安全性

ラベル・formula に使う記号は、フォントで確実に出るものに限る。矢印は `→` `↔`、包含は `⊃`、区切りは `/` を使う。`⇄` など稀な記号はフォント次第で別の字（`≠` 等）に化けることがあるので避ける。コード記号（`->` `::` `$`）はコード行（`lines`）の中だけで使い、ラベルや narration には持ち込まない。

## narration（字幕用原稿）の書き方

- 敬体。writing.md の文体・用語ルールに従う（ダッシュ記号 `—` は使わない）
- **音読して自然な文** にする（字幕は文・読点単位で分割表示され、文字送りされる）
- 1 文 50 字以内を目安に句点で区切る。コード記号の読み上げは避け、口頭の言い回しに直す（`$this->done = true;` →「this が指すインスタンスの done を true にする」）
- **読点「、」を多用しない**。間を作りたいだけの読点（topic の「は」「も」の直後・主語と述語の間・述語の直前など）を打たない。読点は意味の節の切れ目だけに置く。理由は2つ: ①読点過多は音読が途切れて AI 臭が出る（stop-ai-slop-jp の「リズムの均一さ」）。②字幕は narration を句読点で分割して表示し、表示尺は句読点のポーズを加味した重みで配分される（`CaptionOverlay`）。無駄な読点は字幕を細切れにし、音声とのズレを生む。❌「モデルは、AI の頭脳に、あたります。応答も、やや遅くなります」→ ⭕「モデルは AI の頭脳にあたります。応答もやや遅くなります」。各シーンを書いたら読点を数え、削れるものは削る（列挙の「A、B、C」は残す）
- Why → What → How の流れを台本全体で通す。各シーンの narration は前のシーンを受けて自然につながるようにする
- **Section テキストの構成をそのままなぞる**（criteria.md 1.5）。`##` 見出しの並び（概念図の配置も含む）を動画のシーン順にする。動画の都合で並べ替えない。例外はハンズオン部分（実践パートは動画に含めない）だけ。避けるのは同じ見せ方の二重（予告図＋本編シーンで同概念に触れるのは可）
- **冒頭の概念図は予告**（criteria.md 5）。`title` 直後の `figure` で全体像を予告し、`heading` は省く。定義・実演は本編シーンで 1 回だけ担う
- outro シーンの最後は次セクションへの接続文で締める（OUTLINE.md の次セクションのゴールのキーワードを含める）
- **narration では他セクションを番号で引かない（冒頭だけでなく動画全体で）**。「1-3 で」「2-1-3 で学んだ」のように具体的なセクション番号を字幕・音声に出さない。番号は覚えている前提を作り、専門用語めいて入りづらく、音声では特に聞き取りにくい。既習は概念で接続する（「以前」「前のセクションで」「これまで学んだ○○」）。Section のねらいが特定の既習との接続理解にある場合も、概念名でつなげば足りる（参照番号は本文テキストが持つ）。例外は動画共通の UI だけ: title の自セクション番号・右上のセクションチップ（sectionId＋タイトル）・outro の `next` カード（次セクションの番号＋タイトル）は残す。ただし outro の音声・字幕では `next` の番号を読み上げず「次のセクションでは」と言う
- **他セクションの「変わりうる題材・例」を名指しで振り返らない**。別 Section の具体題材（例: 導入のデモで使った特定の題材）は後で差し替わりうる。既習の振り返りは題材を特定せず概念で述べ、具体例が要るときはその Section 内で完結する安定した題材を使う。題材や番号が変わっても動画が陳腐化しないようにする

## 見出し・ラベル・題材の品質（レビューで繰り返し出た崩れ。毎回チェック）

storyboard を書いたら、シーンごとに次を確認する。過去に何度も指摘された崩れなので、最初から避ける。

- **heading は名詞句・トピック名にする**（文・命令形・標語にしない）。❌「エラーを、恐れない」→ ⭕「エラーの読み方」。本文の `##` が疑問形でも、動画側で独自に立てる見出しは名詞句で
- **keypoint のカード `title` は、単独で意味が通る “対の短いラベル”**。ぶら下がった助詞止め・接続詞の断片にしない。❌「モデルは」「ただし」「対処は」→ ⭕「モデルの役割」「例外の扱い」「対処法」。左右が対になる形にそろえる（「認証で確かめること／認可で確かめること」「変更前／変更後」）
- **narration は writing.md に従う**。冒頭を「決めつけ→反転」（「〜なはずです。本教材は〜」）にしない。不安・煽り（「取り残される」等）に寄せない。直接言い切る
- **例・題材は具体的に**。抽象・メタな例でなく、判断や差が見える具体例にする。難しい本題の前に、概念が一発で伝わる簡単な例を 1 枚置く（例: 排他的な分類をまず年齢の区分で見せてから本題へ）
- **fanout の列挙は1枚ずつ**（`fanoutAt` 配列でナレーションに同期）。まとめて出さない。1枚ずつ同期させるなら、ナレーション側でも fanout と同じ並びで各項目を順に言う（言わない項目はチップを音に合わせられない。チップが7個あるのに語るのが3個だけ、にしない）
- **reveal はナレーションで「その語を言う瞬間」に合わせる**（`fanoutAt` / `revealAt` / `rightAt`）。当て推量の等間隔（0.3 / 0.5 / 0.7 等）にしない。**TTS 後に `node scripts/caption-times.mjs <sectionId> [語...]` を実行**し、各語を含む字幕セグメントの開始フラクションを出して、その値からバネ立ち上がりぶん（≒ 0.02〜0.03）手前を `revealAt` / `fanoutAt` に使う（このツールは CaptionOverlay と同じ分割・重み・LEAD を再現するので、reveal と字幕が一致する）。**値を storyboard に入れたら TTS を再実行して props に反映する**（wav は再利用され API は呼ばれない。Studio・レンダが読むのは props.json のため）。keypoint・flow・nest・terminal すべて同じ手順。比率は `audioFrames`（props）に対する値。手で見積もる場合は句読点のポーズも加味する（句点 ≒ 0.45s・読点 ≒ 0.24s 相当）
- **terminal の AI セッションで、後の発話が項目を参照するなら、その項目を先に画面へ出す**。例: ユーザーが「2つ目の〜」と言うなら、直前の `claude` 応答で `\n` 区切りに「1. … / 2. … / 3. …」と実際に列挙してから参照させる。参照対象が画面にないと、視聴者は何を指しているか分からない（提案→選択→適用のような2段の対話で頻出）
- **読みは耳で確認**。誤読しやすい漢字・記号・番号は `reading-pitfalls.md` に従って対策する

## reading（読み上げ原稿）— 通常は書かない

読み上げ音声は **narration から自動生成** される（`scripts/pronounce.mjs`。`tts-gcloud` / `tts-gemini` / `tts-openai` / `tts-voicevox` の**全エンジンに適用**される）。`data/pronunciation.json` の辞書で **英語・技術用語・記号だけをカタカナ化**し、**漢字・かなはそのまま残す**。これはネイティブ TTS（Google Chirp / VOICEVOX 等）が **漢字から正しいアクセントを推定する** ため。漢字をかなに開くと逆に棒読み・誤アクセントになる（過去にこれで失敗した）。

- **新しい英語用語・記号が出たら `pronunciation.json` に追加**する（例 `Task→タスク`・`extends→エクステンズ`）。大小文字は無視されるので 1 エントリで足りる
- 生成前に取り残しを確認: 全シーンの `spokenForScene` 出力を grep し、英字が残っていたら辞書へ追加
- どうしても個別に読み・間を調整したいシーンだけ `scene.reading` を明示する（あれば最優先）
- 話速は `voice.json` の `tempo`（atempo 倍率。再合成不要）。数字の紛れは narration 側で工夫

## 検収（QA）

1. レンダ後、`node scripts/qa-stills.mjs <sectionId>` で全シーンの中間フレームを `out/qa/<sectionId>/` へ書き出し、Read で目視（文字切れ・はみ出し・字幕の重なり・ラベルの化け）
2. 音声を冒頭から試聴（読み・速度・トーン）。読み間違いは SKILL.md の「音声・台本の修正サイクル」で直す（`reading-pitfalls.md` の漢字を含むシーンは特に注意）
3. 尺が 6 分を大きく超えていたら narration を削る（シーンを削るより文を削る）。逆に 3 分に満たず説明が足りないなら、🎯 / ✨ の取りこぼしがないか確認する
