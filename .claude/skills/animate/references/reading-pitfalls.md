# 読みの落とし穴（ナレーションの誤読対策）

ネイティブ TTS（Google Chirp 等）は漢字からアクセント・読みを推定するが、**同じ字で読みが割れる漢字**を文脈と違う読みにすることがある。字幕（`narration`）は読み上げ原稿でもあるため、誤読はそのまま音声に出る。生成後に必ず試聴し、下記の要領で対策する。

## 対策の使い分け

- **読みが一つに定まる語**（その教材で常に同じ読み）→ `video/data/pronunciation.json` に追加する。字幕は漢字のまま・音声だけ正しい読みになる。
  - 例: ある教材で `札` が常に「ふだ」なら `札→ふだ` を登録する（「さつ」と読む文脈がその教材に出てこない場合に限る）
- **読みが割れる漢字**（複合語では別の読みになる）→ 辞書に入れると複合語まで壊れるので入れない。**`narration` 側で、意図した訓読みをひらがなで書く**。
  - 例: `中`→`なか`（ただし「中身＝なかみ」「集中＝しゅうちゅう」は漢字のまま）。`形`→`かたち`（「形式＝けいしき」は漢字のまま）。

## 要注意の漢字（読みが割れやすい）

実際に誤読が出たもの・出やすいもの。新しく見つかったら追記する。

| 漢字 | 意図する読み | 誤読されがち | 対策 |
|---|---|---|---|
| 中 | なか | ちゅう | ひらがな「なか」（中身・集中などの複合語は漢字のまま） |
| 形 | かたち | けい | ひらがな「かたち」（形式は漢字のまま） |
| 表 | あらわ（表す）／おもて | ひょう | 送り仮名で判別されるが要試聴。割れるならひらがな |
| 開 | ひらく（開く） | あく | 「ファイルを開く」は「ひらく」。割れるならひらがな |
| 何 | なに／なん | — | 「何を」＝なに。文脈で確認 |
| 方 | かた（〜方）／ほう | — | 「やり方」＝かた。複合語は概ね正しい |
| 行 | い・ゆ（行く）／ぎょう | — | 文脈で確認 |
| 上・下 | うえ・した／じょう・げ | — | 単独はうえ・した。複合語は音読み |
| 実 | み（実を結ぶ） | じつ | 「実を結ぶ」が「じつ」になりがち。ひらがな「み」か言い換え（「生きてくる」等） |
| 空 | から（空から始まる） | そら／くう | 「空から＝からっぽから」が「そら」になりがち。言い換え（「まっさらな状態から」等）が確実 |

## 記号・番号の誤読

数字をハイフンでつないだ識別子（区間参照 `2-5-3` など）は、**ハイフンが「マイナス」と読まれる**（「に マイナス ご マイナス さん」）。記号始まりではなく数字始まりなので、放置すると毎回マイナスになる。

- **対策**: `pronunciation.json` に「の」区切りの読みで登録する。字幕は `2-5-3` のまま・音声だけ自然になる。
  - 例: `"2-5-3": "にのごのさん"` / `"2-4-4": "にのよんのよん"`（4 は「よん」で固定すると「し」との揺れを防げる）
- ナレーションが参照する区間番号は**動画ごとに違う**ので、新しい動画を作るたびに、その動画で読む区間番号を辞書へ追加する。取りこぼしは `spokenForScene` 出力を `\d+\s*-\s*\d+` で grep して確認する
- `Part6` のような「英字＋数字」は、語境界 `\bPart\b` が数字の直前で切れず変換されないことがある。ナレーションでは「パート6」と直接カタカナで書くのが確実（字幕も同様）
- カタカナの acronym（「エーアイ」等）はイントネーションが揺れることがある。ひらがな開きは逆効果のことがある（「えーあい」は冒頭がフィラーの「えー」と解釈され間延びした実例あり）。試聴で確認する

## 手順

1. `narration` を書いたら、上表の漢字と、ハイフン区間番号（`2-5-3` 等）が含まれていないか確認する。
2. 単一読みの語は `pronunciation.json` に追加、読みが割れる漢字はひらがなにする。
3. TTS 生成後、**冒頭から全体を試聴**して誤読がないか確認する（上表の漢字を含むシーンは特に注意）。
4. 誤読が残っていたら対策して再生成（TTS）・再レンダする。
