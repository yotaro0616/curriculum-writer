# 動画設計の基準

## 0. 密度方針

## 1. 動画の役割 — Section の主たる学習路

動画は Section の **要約でも予告編でもなく、その Section を理解するための主たる学習路** です。学習者は最初に動画を見て Section の内容を理解し、テキストは補助（細部の確認・コピペ・読み返し）として使う、というスタンスで設計します。

したがって動画は、Section の **核となる学びを最後まで成立させる** こと。「何が起きるかの地図だけ渡して本文に丸投げ」はしません。

- Section の 🎯（学ぶこと）と ✨（まとめ）を**すべてカバー**する。中心概念を 1〜2 個に絞って残りを本文へ流す、という作り方はしない
- 解説は **Why（なぜ必要か）→ What（何か）→ How（どう使うか）** の順で組む。導入は本文の「導入（課題・痛み）」に対応させ、🧠（メンター人格の語り）の比喩・実体験と呼応させる
- 各概念は「動画を見ただけで腑に落ちる」レベルまで噛み砕く。定義 → 最小例 → 「だから実務ではこう使う」の接続まで見せる
- ただし **本文に委ねてよいもの** はある: コピペ用の長いコード全文、細かい構文の網羅、外部リンク、コラム（💡/📝/⚠️）の枝葉。動画は「理解の幹」を通し、テキストが「枝葉と再現性」を担う分担にする

## 1.5 テキストの構成をそのままなぞる

動画は Section テキストの再構成であり、動画用に独自構成で組み直さない。**テキストの `##` の並び（概念図の配置も含む）を、そのまま動画のシーンの並びにする**。唯一の例外はハンズオン部分（実践パートは動画に含めない）。学習者がテキストと動画を行き来しても迷わないようにするのが目的。

- **`##` 見出しの順番どおりに進む**: シーンの並びは Section の `##` 見出しの登場順に対応させる。動画の都合で概念を前後させない。一つの `##` を 2 シーンに割るのは可。順序は保つ
- **概念図も配置どおり（冒頭に置く）**: テキストでは概念図は導入末尾にあるので、動画でも `title` 直後に `figure` を 1 枚置く（→ 5）。全 Section でこの位置に揃える（統一感）
- **予告と本編の役割分担（これは重複ではない）**: 冒頭の概念図は「全体像の予告・早見表」、本編シーンは「その概念の作り込んだ解説・実演」。予告と本編が同じ概念に触れるのは想定どおり。避けるのは **同じ見せ方の二重**（例: ターミナル実演を、概念図でもターミナルシーンでも出す＝二重）。予告図の narration は概要にとどめ、定義・実演は本編シーンが 1 回だけ担う

## 2. 尺とシーン数

- **3〜6 分 / 8〜14 シーン**（要約ではなく解説なので、従来の予告編より長い）。ナレーション総量 1,000〜1,800 字（日本語は約 330 字/分）
- 1 シーンのナレーションは 80〜200 字（約 16〜36 秒）。これを超えるならシーンを割る
- Section 本文が短い・概念が少ない場合は下限（3 分 / 8 シーン）に寄せてよい。字数を埋めるための水増しはしない（writing.md と同じ方針）

## 3. シーン型の選び方

| 伝えたいこと | シーン型 | 例 |
|---|---|---|
| Section の開始・主題・導入の問い | `title` | 全 Section の 1 シーン目（固定） |
| 2 つの書き方・状態の対比、エラー体験、コードの読み解き | `codeCompare` | 手続き的 vs OOP、移行前後、誤りと正解 |
| コマンドや AI 操作の実演（シェル／AI エージェント CLI） | `terminal` | pwd/ls/cd と現在地の変化、AI への指示→応答→ツール実行→承認ゲート |
| 指示・操作の良し悪しと出力差の対比（2 セッション並置） | `terminalCompare` | 丸投げの指示 vs 具体的な指示と、出力の質の差 |
| 二項対立・分類・定義の整理 | `keypoint` | 認証 vs 認可、プロパティ vs メソッド |
| 直感的なメンタルモデル（既存概念図の再利用） | `figure` | /illustrate の生成画像（🧠 の比喩を絵にしたもの） |
| 処理・データ・手順・ライフサイクルの流れ | `flow` | リクエスト → 認可 → 処理 → レスポンス |
| 包含関係・階層 | `nest` | 名前空間 ⊃ クラス、`v1` ⊃ コントローラ |
| まとめ + 次への接続 | `outro` | 全 Section の最終シーン（固定） |

- `title` と `outro` は必須。間に 6〜12 シーンを構成し、🎯 と ✨ を取りこぼさない
- 同じ型を連続させてよい（codeCompare 2 連続など）。ただし単調にならないよう、解説の山場では型を切り替える
- **codeCompare のラベル**: 既定で左ペイン＝無彩色グレー、右ペイン＝鋼色アクセントの上辺ラインが自動で付く（`labelColor` は通常指定しない）。特別に色分けしたいときだけ `labelColor` を指定する
- 新しい見せ方が必要なら、シーン型を `video/src/scenes/` に追加してから使う（公式 Skill `remotion-best-practices` のルールに従い `useCurrentFrame()` 駆動で実装し、色は必ず `src/theme.ts` のトークンを参照する）

## 4. デザインの前提（全シーン共通）

- 配色・モーション・フォントは `src/theme.ts` / `src/anim.ts` のトークンに集約（「動き＝ブランド」: 全 Section で同じ語彙）。色・ベベル・モーションを直書きしない。**ブランド固有値（アクセント色・面の淡色・フォント・ロゴ）は `src/brand.ts` に分離**してあり、プロジェクトを変えるときはそこだけ差し替える（→ `customization.md`）
- 全シーン明面。**本編は白**、**タイトル／まとめは淡い面色（`theme.emerald` ＝ `brand.surfaceTint`）** で開幕・締めに区切り感。立体はコンポーネントの**細い段差（ベベル）**で（`theme.edge` ＝上端ハイライト＋ヘアライン枠＋下端の段、`theme.elev*` ＝締まった浮き影）
- **モノクロ＋1アクセント**。構造（面・枠・矢印）は無彩色、アクセントは `theme.accent`（1色）を要所（番号・下線・進捗バー・強調）に。グラデは `theme.accentGrad`、文字は読みやすい `theme.accentText`。2項対比は「アクセント ↔ 無彩色 `theme.markNeutral`」
- コード面は **IDE 風**（`theme.codeBg` ＋ `highlight.ts` のシンタックスハイライト）。字幕は**フロスト＋フェード**（文字送りカラオケ・色の縦バーは使わない＝シックに。表示時に句点「。」を除く）
- フォントは `theme.fontJa`（ブランド指定の日本語ゴシック）＋ コードは JetBrains Mono（`theme.fontMono`）。明朝は使わない
- ロゴは横長ワードマークを**全シーン左上の隅に固定**（`SectionVideo` の `BrandHeader`、`theme.logo`）
- 質感は「シック・エレガント・近未来」。発光・にじみは使わず、ヘアラインと段差で構成する
- モーションは過減衰気味の spring（跳ねない）＋ `STAGGER`。話速は `data/voice.json` の `tempo`。要素の登場は `revealAt`（keypoint / flow / nest / terminal）・`fanoutAt`（flow）・`rightAt`（codeCompare / terminalCompare）でナレーションに同期（実測は `scripts/caption-times.mjs`）
- **Veo / Sora 等の生成動画モデルは本編に使わない**: 画面内テキスト（コード・ラベル・日本語見出し）が崩れるため、教材解説には不適。動画は Remotion のコード描画（決定的レンダリング）で作る

## 5. 挿入位置と画像との共存

- 動画: **Section タイトル直後**（📝 前提知識の行・グループ全体像があればその後、🎯 の前）。学習者が最初に視聴する主経路
- 概念図（/illustrate）: テキストでは従来どおり導入末尾（🧠 コラムの直後）。**動画は概念図を置き換えない**（figure シーンの素材として再利用する関係。白背景の図はライト基調の上で「額装した紙」として馴染む）
- **動画内での図は「冒頭の予告」に使う**: 同じ概念図を、動画では `title` の直後に 1 シーンだけ `figure` で置き、導入の課題と全体像のプレビューにする（テキストの導入末尾と同じ位置づけ）。本編で同概念を 1 回だけ教えるので、予告では教え切らない（→ 1.5）
- **焼き込みタイトルのある figure シーンは `heading` を省く**: 概念図には見出し・まとめが焼き込まれていることが多く、シーンの `heading` を付けるとタイトルが二重になる。予告でも本編でも、焼き込みがあれば `heading` を書かない（`SceneHeading` は空なら何も出さない）
- 図が terminal / codeCompare などネイティブシーンと内容的に重なる場合は、**ネイティブシーンを本編の主役にし、図は予告に回す**（静止画より、ナレーション同期で段階表示されるネイティブシーンの方が動画では分かりやすい）

## 6. 冪等判定

1. Section ファイルのタイトル直後に `releases/download/videos/<sectionId>.mp4` を含む `<video>` タグ → **挿入済み**（スキップ）
2. タグが無く `video/out/<sectionId>.mp4` が存在 → **生成済み・未挿入**（配信と挿入のみ行う）
3. どちらも無い → 未生成（フル実行）
