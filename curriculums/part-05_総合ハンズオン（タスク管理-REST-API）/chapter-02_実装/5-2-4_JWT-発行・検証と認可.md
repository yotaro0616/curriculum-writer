# 5-2-4 JWT 発行・検証と認可

📝 **このハンズオンで使う機能**: JWT の発行・検証（4-1-2 で学習）・認可（自分の資源のみ操作）

## 🎯 このセクションで学ぶこと

- JWT を扱う依存を追加し、秘密鍵を設定から外部注入できる
- `JwtEncoder` / `JwtDecoder` を用意し、ログイン成功時に JWT を発行できる
- `SecurityFilterChain` をステートレス + JWT 検証に切り替えられる
- 認証されたユーザーが、自分のタスクだけを操作できるよう認可を実装できる

JWT の依存と鍵の準備から始め、発行の部品、ログインでの発行、検証への切り替え、そして認可へと進みます。

---

## 導入: サーバが状態を持たずにログインを覚える

5-2-3 では HTTP Basic で認証しました。これは毎回ユーザー名とパスワードを送る方式です。本アプリが目指すのは、4-1-2 で学んだ **ステートレスな JWT 認証** です。ログイン時に署名付きトークンを発行し、以降はそのトークンを `Authorization: Bearer` で携行する。サーバはトークンの署名を検証するだけで身元を判断し、セッションを持ちません。

加えて、ここで **認可** も入れます。認証は「あなたは誰か」、認可は「あなたは何をしてよいか」でした。本アプリのルールは「自分のタスクだけ操作できる」。トークンから復元した「いまログインしているユーザー」を使い、他人のタスクには触れさせないようにします。これで API が実用レベルになります。

### 🧠 先輩エンジニアの思考プロセス

> JWT で最初に腑に落ちなかったのが「サーバが状態を持たないのに、どうやってログインを覚えるのか」でした。答えは「サーバは覚えない。トークン自体が身元の証明を持ち歩く」。署名付きの通行手形を毎回見せる、それだけのことだと分かってからは怖くなくなりました。Spring Security なら発行も検証も標準の部品で完結するので、自分で署名アルゴリズムを書く必要はありません。

> 認可で必ず効くのが「自分の資源だけ」の絞り込みです。私が駆け出しのころ、ID さえ知っていれば他人のデータを取れる API を書いてしまったことがあります。原因は、取得時にユーザーで絞っていなかったこと。以来、所有者チェックは「クエリの段階で必ずユーザーで絞る」を徹底しています。他人の資源は、403 で弾くより **404（見つからない）扱い** にして存在自体を隠すのが安全です。

## 🏃 実践: JWT とユーザーごとの認可

### 🏃 Step 1: JWT の依存と秘密鍵を用意する

4-1-2 で学んだとおり、JWT の発行・検証には Spring Security の JOSE / リソースサーバの機能を使います。Spring Boot 4 では、これらをまとめた Boot スターターを `pom.xml` の `<dependencies>` に追加します（バージョンは親 POM の BOM 任せ）。

```xml
<!-- pom.xml に追加 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security-oauth2-resource-server</artifactId>
</dependency>
```

> 💡 **概念編（4-1-2）の依存名との対応**: 4-1-2 では、JWT を扱う中身のライブラリを `spring-security-oauth2-jose` （トークンの発行・検証）と `spring-security-oauth2-resource-server` （受け取った Bearer トークンの検証フィルタ）の名前で説明しました。Spring Boot 4 では、これらをまとめた Boot スターター `spring-boot-starter-security-oauth2-resource-server` を 1 つ足せば両方が入ります（発行に使う Nimbus を含む jose も推移的に入るため、自前でトークンを発行する本アプリでもこれで足ります）。5-1-2 の他のスターターと同じ流儀に揃います。3.x 系では、このスターターは `spring-boot-starter-oauth2-resource-server` （`security` なし）という名前でした。

秘密鍵と有効期限は、4-3-2 で学んだ `@ConfigurationProperties` で外部化します。秘密鍵はコードに直書きせず、環境変数から注入します。

```yaml
# src/main/resources/application.yml に追加
app:
  jwt:
    secret: ${JWT_SECRET:dev-secret-key-please-change-32bytes-minimum} # 環境変数 JWT_SECRET から注入（開発用の既定値付き）
    expiration: 3600                                                     # 有効期限（秒）= 1 時間
```

```java
// src/main/java/com/example/taskapp/config/JwtProperties.java
package com.example.taskapp.config;

import org.springframework.boot.context.properties.ConfigurationProperties;

@ConfigurationProperties(prefix = "app.jwt")
public class JwtProperties {
    private String secret;       // app.jwt.secret が束縛される
    private long expiration;     // app.jwt.expiration が束縛される
    // getter / setter は IntelliJ で生成
}
```

⚠️ **本番では必ず環境変数で上書きする**: 上の `${JWT_SECRET:...}` は、環境変数 `JWT_SECRET` があればそれを、無ければ既定値（開発用）を使います。この既定値は **開発専用** です。本番では必ず `JWT_SECRET` を十分に長い秘密の値で与えてください（4-3-2）。HS256 は鍵が **32 バイト以上** 必要なので、既定値もそれを満たす長さにしています。

### 🏃 Step 2: 発行・検証の部品を用意する

4-1-2 で学んだ `JwtEncoder`（発行）と `JwtDecoder`（検証）を Bean にします。対称鍵（1 つの秘密鍵で署名・検証する HS256）の構成です。秘密鍵は `JwtProperties` から組み立てます。

```java
// src/main/java/com/example/taskapp/config/JwtConfig.java
package com.example.taskapp.config;

import com.nimbusds.jose.jwk.source.ImmutableSecret;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.JwtDecoder;
import org.springframework.security.oauth2.jwt.JwtEncoder;
import org.springframework.security.oauth2.jwt.NimbusJwtDecoder;
import org.springframework.security.oauth2.jwt.NimbusJwtEncoder;

import javax.crypto.SecretKey;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;

@Configuration
@EnableConfigurationProperties(JwtProperties.class)   // JwtProperties を有効化
public class JwtConfig {

    private final SecretKey secretKey;

    public JwtConfig(JwtProperties properties) {
        // 設定の秘密文字列から HMAC-SHA256 用の鍵を作る
        this.secretKey = new SecretKeySpec(
                properties.getSecret().getBytes(StandardCharsets.UTF_8), "HmacSHA256");
    }

    @Bean
    JwtEncoder jwtEncoder() {                            // 発行側
        return new NimbusJwtEncoder(new ImmutableSecret<>(secretKey));
    }

    @Bean
    JwtDecoder jwtDecoder() {                            // 検証側
        return NimbusJwtDecoder.withSecretKey(secretKey)
                .macAlgorithm(MacAlgorithm.HS256)
                .build();
    }
}
```

発行ロジックは `TokenService` に置きます。ペイロード（クレーム）を組み立てて署名します。トークンの主体（`subject`）にユーザー名を入れるのが肝で、後で検証時にこれが「ログイン中のユーザー」として復元されます。

```java
// src/main/java/com/example/taskapp/service/TokenService.java
package com.example.taskapp.service;

import com.example.taskapp.config.JwtProperties;
import org.springframework.security.oauth2.jwt.JwtClaimsSet;
import org.springframework.security.oauth2.jwt.JwtEncoder;
import org.springframework.security.oauth2.jwt.JwtEncoderParameters;
import org.springframework.stereotype.Service;

import java.time.Instant;

@Service
public class TokenService {

    private final JwtEncoder jwtEncoder;
    private final long expirationSeconds;

    public TokenService(JwtEncoder jwtEncoder, JwtProperties properties) {
        this.jwtEncoder = jwtEncoder;
        this.expirationSeconds = properties.getExpiration();
    }

    public String issueToken(String username) {
        Instant now = Instant.now();
        JwtClaimsSet claims = JwtClaimsSet.builder()
                .issuer("self")
                .subject(username)                              // 誰のトークンか
                .issuedAt(now)
                .expiresAt(now.plusSeconds(expirationSeconds))  // 有効期限
                .build();
        return jwtEncoder.encode(JwtEncoderParameters.from(claims)).getTokenValue();
    }
}
```

### 🏃 Step 3: ログインで JWT を発行する

ログインは「資格情報を検証し、成功したらトークンを発行する」操作です。検証には Spring Security の `AuthenticationManager` を使うので、`SecurityConfig` に Bean として公開します。

```java
// SecurityConfig.java に追加
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;

@Bean
public AuthenticationManager authenticationManager(AuthenticationConfiguration config) throws Exception {
    return config.getAuthenticationManager();
}
```

ログインの入出力 DTO です。

```java
// src/main/java/com/example/taskapp/dto/LoginRequest.java
package com.example.taskapp.dto;

import jakarta.validation.constraints.NotBlank;

public record LoginRequest(@NotBlank String username, @NotBlank String password) {
}
```

```java
// src/main/java/com/example/taskapp/dto/TokenResponse.java
package com.example.taskapp.dto;

public record TokenResponse(String accessToken) {
}
```

`AuthService` にログインを足します。`AuthenticationManager.authenticate` が `UserDetailsService` と `PasswordEncoder` を使って照合し（4-1-2 のフロー）、成功したら `TokenService` でトークンを発行します。5-2-3 の `AuthService` に、`AuthenticationManager` と `TokenService` をコンストラクタへ加え、`login` メソッドを足します。更新後の全体は次のとおりです。

<details>
<summary>更新後の AuthService.java（全体）</summary>

```java
// src/main/java/com/example/taskapp/service/AuthService.java
package com.example.taskapp.service;

import com.example.taskapp.dto.LoginRequest;
import com.example.taskapp.dto.RegisterRequest;
import com.example.taskapp.entity.User;
import com.example.taskapp.exception.DuplicateUsernameException;
import com.example.taskapp.repository.UserRepository;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class AuthService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final AuthenticationManager authenticationManager;   // 追加
    private final TokenService tokenService;                     // 追加

    public AuthService(UserRepository userRepository, PasswordEncoder passwordEncoder,
                       AuthenticationManager authenticationManager, TokenService tokenService) {
        this.userRepository = userRepository;
        this.passwordEncoder = passwordEncoder;
        this.authenticationManager = authenticationManager;
        this.tokenService = tokenService;
    }

    @Transactional
    public void register(RegisterRequest request) {   // 5-2-3 のまま
        if (userRepository.existsByUsername(request.username())) {
            throw new DuplicateUsernameException(request.username());
        }
        String hashed = passwordEncoder.encode(request.password());
        User user = new User(request.username(), request.email(), hashed);
        userRepository.save(user);
    }

    public String login(LoginRequest request) {   // 追加
        Authentication authentication = authenticationManager.authenticate(
                new UsernamePasswordAuthenticationToken(request.username(), request.password()));
        return tokenService.issueToken(authentication.getName());   // 認証成功 → トークン発行
    }
}
```

</details>

ログインエンドポイントを `AuthController` に足します。

import com.example.taskapp.dto.TokenResponse;

照合に失敗すると `AuthenticationManager` が例外を投げます。これを 401 に変換するハンドラを `GlobalExceptionHandler` に足します（どのフィールドが違うかは明かさず、一律のメッセージにします）。

```java
// GlobalExceptionHandler.java に追加
import org.springframework.security.core.AuthenticationException;

@ExceptionHandler(AuthenticationException.class)
public ResponseEntity<ErrorResponse> handleAuthentication(AuthenticationException ex) {
    ErrorResponse body = new ErrorResponse(
            HttpStatus.UNAUTHORIZED.value(), "ユーザー名またはパスワードが正しくありません", null);
    return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body(body);   // 401
}
```

### 🏃 Step 4: SecurityConfig を JWT 検証・ステートレスに切り替える

5-2-3 で HTTP Basic にしていた `SecurityFilterChain` を、JWT 検証 + ステートレスに変更します。4-1-2 のとおり、`oauth2ResourceServer().jwt()` を加えるだけで、`Authorization: Bearer <JWT>` を自動検証するフィルタがチェーンに入ります（`JwtDecoder` が署名と有効期限を確かめます）。

```java
// SecurityConfig.java の filterChain を更新（httpBasic を外し、JWT 検証とステートレスに）
import org.springframework.security.config.http.SessionCreationPolicy;

@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/**").permitAll()   // 登録・ログインは公開
            .anyRequest().authenticated()                  // それ以外は認証必須
        )
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))  // セッションを使わない
        .csrf(csrf -> csrf.disable())                      // トークン認証では CSRF 保護は不要
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));            // JWT を検証
    return http.build();
}
```

検証に成功すると、Spring Security はトークンの `subject`（ユーザー名）から認証情報を組み立て、リクエストの間 `SecurityContext` に入れてくれます。コントローラは認証チェックを書かずに「認証済みの前提」で処理できます。

### 🏃 Step 5: 認可（自分のタスクのみ）を実装する

ここが認可の本体です。方針は「**クエリの段階で必ずログイン中ユーザーで絞る**」。まず `TaskRepository` に、ユーザー単位の取得を足します。

```java
// TaskRepository.java にメソッドを追加
import org.springframework.data.repository.query.Param;
import java.util.Optional;

// ログイン中ユーザーのタスク一覧（タグも fetch join）
@Query("select distinct t from Task t left join fetch t.tags where t.user.username = :username")
List<Task> findByUsernameWithTags(@Param("username") String username);

// id とユーザー名の両方が一致するタスク（他人のは取れない）
Optional<Task> findByIdAndUserUsername(Long id, String username);
```

> 💡 **派生クエリの細かな作法**: `findByIdAndUserUsername` は、Spring Data が「`id` と `user.username` の一致」と解釈して動きます。関連の区切りを明示したいときは `findByIdAndUser_Username` （`_` で区切る）と書く正攻法もあります。なお、5-2-2 で追加した `findAllWithTags()` は、ここで作るユーザー単位の `findByUsernameWithTags` に役割が移るので、もう使いません（残してもビルドは通りますが、削除して構いません）。

次に `TaskService` を、すべてのメソッドが **ユーザー名を受け取り、そのユーザーのタスクだけ** を扱うように更新します（5-2-2 の `TaskService` を次の内容に置き換えます。`UserRepository` を注入に追加し、作成時に所有者を結びつけます）。

```java
// src/main/java/com/example/taskapp/service/TaskService.java（ユーザー単位に更新）
package com.example.taskapp.service;

import com.example.taskapp.dto.TaskCreateRequest;
import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.dto.TaskUpdateRequest;
import com.example.taskapp.entity.Tag;
import com.example.taskapp.entity.Task;
import com.example.taskapp.entity.User;
import com.example.taskapp.exception.TaskNotFoundException;
import com.example.taskapp.repository.TagRepository;
import com.example.taskapp.repository.TaskRepository;
import com.example.taskapp.repository.UserRepository;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.HashSet;
import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

@Service
public class TaskService {

    private static final Logger log = LoggerFactory.getLogger(TaskService.class);

    private final TaskRepository taskRepository;
    private final TagRepository tagRepository;
    private final UserRepository userRepository;

    public TaskService(TaskRepository taskRepository, TagRepository tagRepository,
                       UserRepository userRepository) {
        this.taskRepository = taskRepository;
        this.tagRepository = tagRepository;
        this.userRepository = userRepository;
    }

    @Transactional(readOnly = true)
    public List<TaskResponse> findAll(String username) {
        return taskRepository.findByUsernameWithTags(username).stream()
                .map(this::toResponse)
                .toList();
    }

    @Transactional(readOnly = true)
    public TaskResponse findById(String username, Long id) {
        Task task = taskRepository.findByIdAndUserUsername(id, username)
                .orElseThrow(() -> new TaskNotFoundException(id));   // 他人のタスクも 404 扱い
        return toResponse(task);
    }

    @Transactional
    public TaskResponse create(String username, TaskCreateRequest request) {
        User owner = userRepository.findByUsername(username)
                .orElseThrow(() -> new UsernameNotFoundException(username));
        Task task = new Task(request.title(), request.description(), request.dueDate());
        task.setUser(owner);                            // 所有者を結びつける
        task.setTags(resolveTags(request.tags()));
        Task saved = taskRepository.save(task);
        log.info("タスクを作成しました: id={}, user={}", saved.getId(), username);
        return toResponse(saved);
    }

    @Transactional
    public TaskResponse update(String username, Long id, TaskUpdateRequest request) {
        Task task = taskRepository.findByIdAndUserUsername(id, username)
                .orElseThrow(() -> new TaskNotFoundException(id));
        task.setTitle(request.title());
        task.setDone(request.done());
        task.setDueDate(request.dueDate());
        task.setTags(resolveTags(request.tags()));
        return toResponse(taskRepository.save(task));
    }

    @Transactional
    public void delete(String username, Long id) {
        Task task = taskRepository.findByIdAndUserUsername(id, username)
                .orElseThrow(() -> new TaskNotFoundException(id));
        taskRepository.delete(task);
    }

    private Set<Tag> resolveTags(Set<String> names) {
        if (names == null) {
            return new HashSet<>();
        }
        return names.stream()
                .map(name -> tagRepository.findByName(name)
                        .orElseGet(() -> tagRepository.save(new Tag(name))))
                .collect(Collectors.toSet());
    }

    private TaskResponse toResponse(Task task) {
        List<String> tagNames = task.getTags().stream()
                .map(Tag::getName)
                .sorted()
                .toList();
        return new TaskResponse(
                task.getId(), task.getTitle(), task.getDescription(),
                task.isDone(), task.getDueDate(), tagNames);
    }
}
```

最後に `TaskController` を、`Authentication` から「いまログイン中のユーザー名」を取り出して Service に渡すように更新します。`authentication.getName()` が、JWT の `subject` に入れたユーザー名です。

```java
// src/main/java/com/example/taskapp/controller/TaskController.java（Authentication を受け取るよう更新）
package com.example.taskapp.controller;

import com.example.taskapp.dto.TaskCreateRequest;
import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.dto.TaskUpdateRequest;
import com.example.taskapp.service.TaskService;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.security.core.Authentication;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    private final TaskService taskService;

    public TaskController(TaskService taskService) {
        this.taskService = taskService;
    }

    @GetMapping
    public List<TaskResponse> findAll(Authentication authentication) {
        return taskService.findAll(authentication.getName());
    }

    @GetMapping("/{id}")
    public TaskResponse findById(Authentication authentication, @PathVariable Long id) {
        return taskService.findById(authentication.getName(), id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public TaskResponse create(Authentication authentication, @Valid @RequestBody TaskCreateRequest request) {
        return taskService.create(authentication.getName(), request);
    }

    @PutMapping("/{id}")
    public TaskResponse update(Authentication authentication, @PathVariable Long id,
                               @Valid @RequestBody TaskUpdateRequest request) {
        return taskService.update(authentication.getName(), id, request);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(Authentication authentication, @PathVariable Long id) {
        taskService.delete(authentication.getName(), id);
    }
}
```

🔑 **認可の要は「クエリで絞る」**: 取得・更新・削除はすべて `findByIdAndUserUsername(id, username)` を通すので、他人のタスクの id を指定しても **見つからず 404** になります。一覧も `findByUsernameWithTags(username)` で自分の分だけ。こうして「自分のタスクのみ操作」が、特別な分岐を増やさずクエリの絞り込みだけで実現できます。

### 🏃 Step 6: 動作確認する

アプリを起動し（MySQL 起動済み）、登録 → ログイン → トークンで操作、の流れを確かめます。

```bash
# ① 登録（5-2-3 で alice 登録済みならスキップ可）
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","email":"alice@example.com","password":"password123"}'

# ② ログイン → トークン取得
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"password123"}'
# → {"accessToken":"eyJhbGciOiJIUzI1NiJ9..."}

# ③ トークンを使ってタスク作成（自分のタスクになる）
curl -X POST http://localhost:8080/api/tasks \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '{"title":"自分のタスク","tags":["仕事"]}'

# ④ 一覧（自分のタスクだけ返る）
curl http://localhost:8080/api/tasks -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."

# ⑤ トークンなし → 401
curl -i http://localhost:8080/api/tasks
```

`②` で受け取った `accessToken` を `③`〜`④` の `Bearer` に貼り付けます。別のユーザーでログインして同じ一覧を叩くと、相手には自分のタスクが一切見えないことも確認できます。これで認証（JWT）と認可（自分のタスクのみ）が通りました。

> ⚠️ **よくあるエラー**: タスク取得時に 500 エラーと、次のようなログが出る場合があります。
>
> ```
> The secret key's size must be greater than or equal to ... HS256
> ```
>
> **原因**: `app.jwt.secret` が短すぎます。HS256 は鍵が 32 バイト以上必要です。
>
> **対処法**: `application.yml` の既定値（または環境変数 `JWT_SECRET`）を 32 文字以上の値にします。

## ✨ まとめ

- JWT は Boot スターター `spring-boot-starter-security-oauth2-resource-server` （jose ＋ リソースサーバを内包）で扱う。秘密鍵は `@ConfigurationProperties` + 環境変数で外部化する（4-3-2）
- 発行は `JwtEncoder`（`subject` にユーザー名）、検証は `oauth2ResourceServer().jwt()` + `JwtDecoder`。`SessionCreationPolicy.STATELESS` でセッションを持たない（4-1-2）
- ログインは `AuthenticationManager.authenticate` で照合し、成功したらトークンを発行。失敗は 401
- 認可は「クエリでログイン中ユーザーに絞る」。`findByIdAndUserUsername` により他人のタスクは 404 になり、存在を隠せる。ユーザー名は `Authentication.getName()`（JWT の `subject`）から得る
