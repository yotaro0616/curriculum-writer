## 導入: データ層の上に「縦串」を通す

5-2-1 でデータ層（エンティティとリポジトリ）ができました。次は、その上に Service（ビジネスロジック）と Controller（Web 入出力）を載せ、「リクエストが来て、JSON が返る」までの **縦串** を通します。3-2-2 で学んだとおり、依存は Controller → Service → Repository の一方向です。Controller はリクエストを受けて Service に委ね、Service が Repository を使う。この規律を守れば、責務がきれいに分かれます。

CT で Laravel のコントローラ + FormRequest + API リソースを書いた構成を、Java では Controller + DTO + Service + `@RestControllerAdvice` で再現します。役者は増えますが、一つひとつは Part 3 で学んだものばかりです。

### 🧠 先輩エンジニアの思考プロセス

> Laravel から来ると、最初に戸惑うのが「Service 層って要る？」です。Laravel ではコントローラに業務ロジックを書いても回っていました。Java の現場では Service を挟むのが基本で、理由はテストのしやすさと再利用です。コントローラは HTTP の受け渡しだけ、業務判断は Service、という線引きがあると、Service だけを単体テストでき（5-3-1 でやります）、同じロジックを別の入口からも呼べます。

> もう一つ伝えたいのが、エンティティをそのまま JSON で返さないことです。私は昔、エンティティを直接返して、パスワードのハッシュまで API に漏らしかけたことがあります。DTO を挟むのは面倒に見えて、「外に見せていいものだけを器に詰める」という安全装置なんです。3-3-2 で学んだ「入力用と出力用を分ける」を、ここで徹底します。

## 🏃 実践: CRUD の API を完成させる

### 🏃 Step 1: いったん全許可のセキュリティ設定を置く

5-1-2 で Spring Security を依存に入れたので、いまは既定で全エンドポイントが認証必須（401）です。このセクションは API のロジックに集中したいので、**いったん全リクエストを許可する** 暫定設定を置きます。

```java
// src/main/java/com/example/taskapp/config/SecurityConfig.java（暫定版）
package com.example.taskapp.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth.anyRequest().permitAll())  // 暫定: 全許可
            .csrf(csrf -> csrf.disable());                                  // 暫定: CSRF 無効
        return http.build();
    }
}
```

⚠️ **これは暫定です**: この設定では誰でも全 API を叩けます。CRUD の動作確認に集中するための一時的なものです。**5-2-3 で、このファイルを本物の認証設定に置き換えます**。`csrf` を無効にしているのは、`curl` での POST 確認を通すためです（API をステートレスにする 5-2-4 で正式に無効化します）。

### 🏃 Step 2: DTO を record で定義する

3-3-2 で学んだとおり、入力用（リクエスト）と出力用（レスポンス）の DTO を分けます。すべて `dto` パッケージに置きます。タグはタグ名の集合（`Set<String>`）でやり取りします。

```java
// src/main/java/com/example/taskapp/dto/TaskCreateRequest.java
package com.example.taskapp.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import java.time.LocalDate;
import java.util.Set;

public record TaskCreateRequest(
        @NotBlank @Size(max = 100) String title,   // 必須・100 文字以内
        @Size(max = 1000) String description,        // 任意・1000 文字以内
        LocalDate dueDate,
        Set<String> tags                              // タグ名の集合（任意）
) {
}
```

```java
// src/main/java/com/example/taskapp/dto/TaskUpdateRequest.java
package com.example.taskapp.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import java.time.LocalDate;
import java.util.Set;

public record TaskUpdateRequest(
        @NotBlank @Size(max = 100) String title,
        boolean done,                                 // 完了状態の切り替えを含む
        LocalDate dueDate,
        Set<String> tags
) {
}
```

```java
// src/main/java/com/example/taskapp/dto/TaskResponse.java
package com.example.taskapp.dto;

import java.time.LocalDate;
import java.util.List;

public record TaskResponse(
        Long id,
        String title,
        String description,
        boolean done,
        LocalDate dueDate,
        List<String> tags                             // タグ名の一覧
) {
}
```

💡 **3-3-2 の DTO からの拡張**: 3-3-2 では `TaskResponse(id, title, done, dueDate)` を最小構成で設計しました。本アプリでは説明とタグも返したいので、`description` と `tags`（タグ名の一覧）を加えています。入力 DTO に `id` や `done` を含めない原則（サーバが決める値はクライアントから受け取らない）はそのままです。record を JSON に変換するのは Jackson の役目で、こちらでの設定は不要です（3-3-2）。

### 🏃 Step 3: 例外と統一エラーレスポンスを用意する

3-3-3 で学んだ統一エラーの仕組みを作ります。まず、タスクが見つからないときの例外です。

```java
// src/main/java/com/example/taskapp/exception/TaskNotFoundException.java
package com.example.taskapp.exception;

public class TaskNotFoundException extends RuntimeException {
    public TaskNotFoundException(Long id) {
        super("タスクが見つかりません: id=" + id);
    }
}
```

エラーレスポンスの器（record）と、それを組み立てる `@RestControllerAdvice` です。

```java
// src/main/java/com/example/taskapp/dto/ErrorResponse.java
package com.example.taskapp.dto;

import java.util.List;

public record ErrorResponse(
        int status,                  // HTTP ステータスコード
        String message,              // 全体的なエラーメッセージ
        List<FieldError> errors      // フィールドごとのエラー（検証エラー以外では null）
) {
    public record FieldError(String field, String message) {   // ネストした record
    }
}
```

```java
// src/main/java/com/example/taskapp/exception/GlobalExceptionHandler.java
package com.example.taskapp.exception;

import com.example.taskapp.dto.ErrorResponse;
import com.example.taskapp.dto.ErrorResponse.FieldError;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.List;

@RestControllerAdvice
public class GlobalExceptionHandler {

    // タスクが見つからない → 404
    @ExceptionHandler(TaskNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleTaskNotFound(TaskNotFoundException ex) {
        ErrorResponse body = new ErrorResponse(HttpStatus.NOT_FOUND.value(), ex.getMessage(), null);
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(body);
    }

    // 入力検証エラー → 400
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException ex) {
        List<FieldError> fieldErrors = ex.getBindingResult().getFieldErrors().stream()
                .map(e -> new FieldError(e.getField(), e.getDefaultMessage()))
                .toList();
        ErrorResponse body = new ErrorResponse(
                HttpStatus.BAD_REQUEST.value(), "入力内容に誤りがあります", fieldErrors);
        return ResponseEntity.badRequest().body(body);
    }
}
```

これで、`TaskNotFoundException` が投げられれば 404、`@Valid` の検証に失敗すれば 400 が、いずれも統一された形の JSON で返ります。Controller には例外処理を書かなくて済みます（4-3-1 で学んだ「Service が投げ、Advice が変換し、Controller は素通り」）。

### 🏃 Step 4: Service にビジネスロジックを書く

`@Service` に CRUD のロジックを書きます。書き込みメソッドには `@Transactional`、読み取りには `@Transactional(readOnly = true)` を付けます（3-4-3）。タグ名から `Tag` を引く（無ければ作る）処理と、エンティティ → DTO の変換もここに置きます。

```java
// src/main/java/com/example/taskapp/service/TaskService.java
package com.example.taskapp.service;

import com.example.taskapp.dto.TaskCreateRequest;
import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.dto.TaskUpdateRequest;
import com.example.taskapp.entity.Tag;
import com.example.taskapp.entity.Task;
import com.example.taskapp.exception.TaskNotFoundException;
import com.example.taskapp.repository.TagRepository;
import com.example.taskapp.repository.TaskRepository;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.HashSet;
import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

@Service
public class TaskService {

    private static final Logger log = LoggerFactory.getLogger(TaskService.class);

    private final TaskRepository taskRepository;
    private final TagRepository tagRepository;

    public TaskService(TaskRepository taskRepository, TagRepository tagRepository) {
        this.taskRepository = taskRepository;
        this.tagRepository = tagRepository;
    }

    @Transactional(readOnly = true)
    public List<TaskResponse> findAll() {
        return taskRepository.findAllWithTags().stream()   // fetch join（Step 7 で追加）
                .map(this::toResponse)
                .toList();
    }

    @Transactional(readOnly = true)
    public TaskResponse findById(Long id) {
        Task task = taskRepository.findById(id)
                .orElseThrow(() -> new TaskNotFoundException(id));
        return toResponse(task);
    }

    @Transactional
    public TaskResponse create(TaskCreateRequest request) {
        Task task = new Task(request.title(), request.description(), request.dueDate());
        task.setTags(resolveTags(request.tags()));
        Task saved = taskRepository.save(task);
        log.info("タスクを作成しました: id={}", saved.getId());   // 業務の節目を INFO で（4-3-1）
        return toResponse(saved);
    }

    @Transactional
    public TaskResponse update(Long id, TaskUpdateRequest request) {
        Task task = taskRepository.findById(id)
                .orElseThrow(() -> new TaskNotFoundException(id));
        task.setTitle(request.title());
        task.setDone(request.done());
        task.setDueDate(request.dueDate());
        task.setTags(resolveTags(request.tags()));
        return toResponse(taskRepository.save(task));
    }

    @Transactional
    public void delete(Long id) {
        if (!taskRepository.existsById(id)) {
            throw new TaskNotFoundException(id);
        }
        taskRepository.deleteById(id);
    }

    // タグ名の集合を Tag の集合に変換する。同名タグがあれば再利用し、無ければ作る
    private Set<Tag> resolveTags(Set<String> names) {
        if (names == null) {
            return new HashSet<>();
        }
        return names.stream()
                .map(name -> tagRepository.findByName(name)
                        .orElseGet(() -> tagRepository.save(new Tag(name))))
                .collect(Collectors.toSet());
    }

    // エンティティ → レスポンス DTO（タグはタグ名の一覧に）
    private TaskResponse toResponse(Task task) {
        List<String> tagNames = task.getTags().stream()
                .map(Tag::getName)
                .sorted()
                .toList();
        return new TaskResponse(
                task.getId(),
                task.getTitle(),
                task.getDescription(),
                task.isDone(),        // boolean の getter は isDone()
                task.getDueDate(),
                tagNames
        );
    }
}
```

💡 **`@Transactional` の import に注意**: 3-4-3 で学んだとおり、`readOnly` などを使えるのは Spring 版の `org.springframework.transaction.annotation.Transactional` です。`jakarta.transaction.Transactional` ではないので、IDE の補完で取り違えないようにします。

### 🏃 Step 5: Controller でエンドポイントを公開する

3-3-1 / 3-3-3 で設計したとおり、`@RestController` に CRUD のエンドポイントを並べます。作成と削除はステータスコードを `@ResponseStatus` で固定し、入力は `@Valid` で検証します。

```java
// src/main/java/com/example/taskapp/controller/TaskController.java
package com.example.taskapp.controller;

import com.example.taskapp.dto.TaskCreateRequest;
import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.dto.TaskUpdateRequest;
import com.example.taskapp.service.TaskService;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    private final TaskService taskService;

    public TaskController(TaskService taskService) {
        this.taskService = taskService;
    }

    @GetMapping                              // GET /api/tasks
    public List<TaskResponse> findAll() {
        return taskService.findAll();
    }

    @GetMapping("/{id}")                     // GET /api/tasks/{id}
    public TaskResponse findById(@PathVariable Long id) {
        return taskService.findById(id);     // 無ければ 404（GlobalExceptionHandler が変換）
    }

    @PostMapping                             // POST /api/tasks
    @ResponseStatus(HttpStatus.CREATED)      // 201
    public TaskResponse create(@Valid @RequestBody TaskCreateRequest request) {
        return taskService.create(request);
    }

    @PutMapping("/{id}")                     // PUT /api/tasks/{id}
    public TaskResponse update(@PathVariable Long id, @Valid @RequestBody TaskUpdateRequest request) {
        return taskService.update(id, request);
    }

    @DeleteMapping("/{id}")                  // DELETE /api/tasks/{id}
    @ResponseStatus(HttpStatus.NO_CONTENT)   // 204
    public void delete(@PathVariable Long id) {
        taskService.delete(id);
    }
}
```

### 🏃 Step 7: N+1 を観察して fetch join で抑える

一覧取得では、各タスクのタグ名を取り出すために `task.getTags()` にアクセスします。タグは多対多（遅延フェッチ）なので、素朴に `taskRepository.findAll()` で取ると、**タスクの一覧で 1 回 + 各タスクのタグ取得で N 回** のクエリが飛びます。これが 3-4-3 で学んだ N+1 問題です。タスクが 3 件あると、ログにはこうなります（以下は要点を簡略化したログのイメージで、実際は列名が展開された SQL が出ます）。

```text
Hibernate: select t.* from tasks t                       -- ① 一覧（1 回）
Hibernate: select tag.* from task_tags ... where task_id=1  -- ② 1 件目のタグ
Hibernate: select tag.* from task_tags ... where task_id=2  -- ③ 2 件目のタグ
Hibernate: select tag.* from task_tags ... where task_id=3  -- ④ 3 件目のタグ
```

対策は、タスクとタグを **一度に取る** fetch join です。`TaskRepository` にクエリを足します。

```java
// src/main/java/com/example/taskapp/repository/TaskRepository.java（メソッドを追加）
import org.springframework.data.jpa.repository.Query;
import java.util.List;

public interface TaskRepository extends JpaRepository<Task, Long> {

    // タスクとタグをまとめて取得（N+1 を避ける）
    @Query("select distinct t from Task t left join fetch t.tags")
    List<Task> findAllWithTags();
}
```

Step 4 の `findAll()` はこの `findAllWithTags()` を呼ぶようにしてあります。これで一覧のクエリは 1 回にまとまります。

```text
Hibernate: select distinct t.*, tag.* from tasks t left join task_tags ... left join tags tag ...
```

⚠️ **複数のコレクションを同時に fetch join しない**: 3-4-3 で触れたとおり、`tags` のような「多」のコレクションを **2 つ以上** 同時に fetch join すると、行が掛け算で増えて重複します。ここで結合しているコレクションは `tags` の 1 つだけなので問題ありません。`distinct` は、結合で増えた重複行をまとめるために付けています。

## ✨ まとめ

- データ層の上に Service と Controller を載せ、リクエスト → JSON の縦串を通す。依存は Controller → Service → Repository の一方向（3-2-2）

- 一覧のタグ取得で起きる N+1 を、`left join fetch` の派生クエリで 1 回にまとめる（3-4-3）
- セキュリティはこの段階では暫定で全許可。次から本物の認証に置き換える
