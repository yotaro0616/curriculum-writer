# 5-3-1 テストを書く

📝 **このハンズオンで使う機能**: JUnit・Mockito による単体テスト（4-2-1 で学習）・`@WebMvcTest` / `MockMvc` / `@SpringBootTest`（4-2-2 で学習）

## 🎯 このセクションで学ぶこと

- Mockito で依存をモックに差し替え、Service の単体テストを書ける
- `@WebMvcTest` と `MockMvc` で Controller のテストを書ける（`@MockitoBean`・`@WithMockUser`・CSRF）
- `@SpringBootTest` で、登録 → ログイン → 操作までの統合テストを書ける
- 層に応じてテストの種類を選べる

Service の単体テストから始め、Controller の MockMvc テスト、アプリ全体の統合テスト、そして実行へと進みます。

---

## 導入: 手で確かめ続けるのは限界がある

5-2 で動く API ができました。ここまでは `curl` で手動確認してきましたが、変更のたびに全エンドポイントを手で叩き直すのは現実的ではありません。CT で Laravel の Feature テストを書いて API を自動検証した経験を、ここで `JUnit` / `Mockito` / `MockMvc` に置き換えます。

4-2 で学んだとおり、テストは層に応じて種類を選びます。ビジネスロジックだけを速く確かめたいなら **単体テスト** （Spring を起動しない）、Controller の入出力を確かめたいなら **`@WebMvcTest`** （Web 層だけ）、複数層をまたいで本物に近い形で確かめたいなら **`@SpringBootTest`** （アプリ全体）。この 3 つを、本アプリに対して書いていきます。

### 🧠 先輩エンジニアの思考プロセス

> テストで一番効くのは、異常系を押さえることです。正常系は手でも気づけますが、「他人のタスクは取れない」「不正な入力は弾く」といった条件は、手動だと確認を忘れがちです。私は認可まわりを実装したら、必ず「自分のだけ取れる」をテストに固定します。一度書けば、後でリファクタしても認可が壊れていないことを自動で保証してくれる。これが安心して変更を続けられる土台になります。

> もう一つ、Spring Boot 4 でのつまずきポイントを先に言っておきます。モック Bean のアノテーションが `@MockBean` から `@MockitoBean` に変わりました。世の中の記事の多くはまだ `@MockBean` で書かれていて、そのまま真似るとコンパイルが通りません。新しい名前を最初から使ってください。詳しくはこのあとのエラー解説で触れます。

## 🏃 実践: 3 種類のテストを書く

テストコードは、本体と同じパッケージ構成で `src/test/java/com/example/taskapp/` の下に置きます。

### 🏃 Step 1: Service の単体テスト（Mockito）

Service のロジックだけを、Spring を起動せずに確かめます。4-2-1 で学んだ `@ExtendWith(MockitoExtension.class)`・`@Mock`・`@InjectMocks` を使い、リポジトリをモックに差し替えます。

```java
// src/test/java/com/example/taskapp/service/TaskServiceTest.java
package com.example.taskapp.service;

import com.example.taskapp.dto.TaskCreateRequest;
import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.entity.Task;
import com.example.taskapp.entity.User;
import com.example.taskapp.exception.TaskNotFoundException;
import com.example.taskapp.repository.TagRepository;
import com.example.taskapp.repository.TaskRepository;
import com.example.taskapp.repository.UserRepository;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import java.util.Optional;
import java.util.Set;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.mockito.ArgumentMatchers.any;
import static org.mockito.Mockito.when;

@ExtendWith(MockitoExtension.class)   // Mockito を有効化（Spring は起動しない）
class TaskServiceTest {

    @Mock private TaskRepository taskRepository;
    @Mock private TagRepository tagRepository;
    @Mock private UserRepository userRepository;

    @InjectMocks private TaskService taskService;   // モックが注入される

    @Test
    @DisplayName("作成すると、保存したタスクが DTO で返る")
    void create_returnsResponse() {
        User alice = new User("alice", "alice@example.com", "{bcrypt}xxx");
        when(userRepository.findByUsername("alice")).thenReturn(Optional.of(alice));
        when(taskRepository.save(any(Task.class))).thenAnswer(inv -> inv.getArgument(0));

        TaskCreateRequest request = new TaskCreateRequest("買い物", "牛乳", null, Set.of());
        TaskResponse result = taskService.create("alice", request);

        assertThat(result.title()).isEqualTo("買い物");
        assertThat(result.done()).isFalse();
    }

    @Test
    @DisplayName("自分のタスクに無い id なら、TaskNotFoundException を投げる")
    void findById_whenNotOwned_throws() {
        when(taskRepository.findByIdAndUserUsername(999L, "alice")).thenReturn(Optional.empty());

        assertThatThrownBy(() -> taskService.findById("alice", 999L))
                .isInstanceOf(TaskNotFoundException.class);
    }
}
```

検証は 4-2-1 で中心に据えた AssertJ（`assertThat(...)`・`assertThatThrownBy(...)`）です。`when(...).thenReturn(...)` でモックの振る舞いを仕込み、`thenAnswer` で「保存したものをそのまま返す」を表現しています。2 つ目のテストは、他人のタスク（自分の id に無い）を取ろうとすると例外になることを固定しています（5-2-4 の認可）。

### 🏃 Step 2: Controller の MockMvc テスト

Web 層だけを起動し、擬似 HTTP リクエストで Controller を確かめます。4-2-2 で学んだ `@WebMvcTest` + `MockMvc` です。依存する Service は `@MockitoBean` でモックに差し替えます。

```java
// src/test/java/com/example/taskapp/controller/TaskControllerTest.java
package com.example.taskapp.controller;

import com.example.taskapp.dto.TaskResponse;
import com.example.taskapp.service.TaskService;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.security.test.context.support.WithMockUser;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.MockMvc;

import java.time.LocalDate;
import java.util.List;

import static org.mockito.Mockito.when;
import static org.springframework.security.test.web.servlet.request.SecurityMockMvcRequestPostProcessors.csrf;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(TaskController.class)   // Web 層だけ起動（この Controller に絞る）
class TaskControllerTest {

    @Autowired private MockMvc mockMvc;

    @MockitoBean private TaskService taskService;   // 依存 Service はモック Bean に

    @Test
    @WithMockUser(username = "alice")               // 認証済みユーザーとして実行
    void getTasks_returnsJson() throws Exception {
        when(taskService.findAll("alice")).thenReturn(List.of(
                new TaskResponse(1L, "買い物", "牛乳", false, LocalDate.of(2026, 6, 30), List.of("急ぎ"))));

        mockMvc.perform(get("/api/tasks"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$[0].title").value("買い物"))
                .andExpect(jsonPath("$[0].tags[0]").value("急ぎ"));
    }

    @Test
    @WithMockUser(username = "alice")
    void createTask_whenTitleBlank_returns400() throws Exception {
        String body = "{\"title\":\"\",\"description\":\"x\"}";
        mockMvc.perform(post("/api/tasks").with(csrf())              // POST は CSRF トークンが要る
                        .contentType("application/json").content(body))
                .andExpect(status().isBadRequest())
                .andExpect(jsonPath("$.errors[0].field").value("title"));
    }
}
```

`@WithMockUser(username = "alice")` で「alice として認証済み」の状態を作るので、Controller の `Authentication.getName()` は `"alice"` になり、`taskService.findAll("alice")` が呼ばれます（Laravel の `actingAs($user)` に対応）。2 つ目はバリデーション（空の `title`）が 400 と統一エラーを返すことを確かめています。

⚠️ **`@WebMvcTest` での POST には `csrf()` が要る**: `@WebMvcTest` の既定のセキュリティ設定では CSRF 保護が有効です（本番の `SecurityConfig` では無効にしましたが、スライステストには読み込まれません）。そのため POST / PUT / DELETE のテストには `.with(csrf())` を付けます。GET には不要です。

> ⚠️ **よくあるエラー**: `@MockBean` を import しようとするとコンパイルが通りません。
>
> ```
> cannot find symbol: class MockBean
> ```
>
> **原因**: 長く使われてきた `@MockBean` は Spring Boot 4.0 で削除されました（世の中の記事の大半はまだ `@MockBean` です）。
>
> **対処法**: 後継の **`@MockitoBean`** （`org.springframework.test.context.bean.override.mockito` パッケージ）を使います。

💡 **Repository だけを試すなら `@DataJpaTest`**: 4-2-2 で学んだ `@DataJpaTest` を使うと、データ層だけを起動して派生クエリなどを確かめられます。実 MySQL に対して試すには `@AutoConfigureTestDatabase(replace = Replace.NONE)` を添えます。本セクションでは、次の統合テストがデータ層も含めて通すので割愛します。

### 🏃 Step 3: アプリ全体の統合テスト

最後に、アプリ全体を起動して「登録 → ログイン → トークンで操作」までを通しで確かめます。4-2-2 の `@SpringBootTest` + `@AutoConfigureMockMvc` です。本物の `SecurityConfig`（JWT・ステートレス）が読み込まれるので、実際のトークンを発行して使います。

```java
// src/test/java/com/example/taskapp/TaskApiIntegrationTest.java
package com.example.taskapp;

import com.jayway.jsonpath.JsonPath;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.transaction.annotation.Transactional;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest              // アプリ全体を起動
@AutoConfigureMockMvc        // MockMvc を使えるようにする
@Transactional               // テストごとに DB をロールバック
class TaskApiIntegrationTest {

    @Autowired private MockMvc mockMvc;

    @Test
    void registerLoginThenCreateTask() throws Exception {
        // ① 登録 → 201
        mockMvc.perform(post("/api/auth/register")
                        .contentType("application/json")
                        .content("{\"username\":\"bob\",\"email\":\"bob@example.com\",\"password\":\"password123\"}"))
                .andExpect(status().isCreated());

        // ② ログイン → トークンを取り出す
        String json = mockMvc.perform(post("/api/auth/login")
                        .contentType("application/json")
                        .content("{\"username\":\"bob\",\"password\":\"password123\"}"))
                .andExpect(status().isOk())
                .andReturn().getResponse().getContentAsString();
        String token = JsonPath.read(json, "$.accessToken");

        // ③ トークンを付けてタスク作成 → 201
        mockMvc.perform(post("/api/tasks")
                        .header("Authorization", "Bearer " + token)
                        .contentType("application/json")
                        .content("{\"title\":\"統合テストのタスク\"}"))
                .andExpect(status().isCreated());

        // ④ トークンなしの一覧 → 401
        mockMvc.perform(get("/api/tasks")).andExpect(status().isUnauthorized());
    }
}
```

このテストは、JWT の発行・検証から認可までを本物の設定で通します。`@Transactional` を付けているので、登録したユーザーや作成したタスクはテスト終了時に **ロールバック** され、DB に残りません（4-2-2 で触れた、Laravel の `RefreshDatabase` に当たる仕組みです）。本物の `SecurityConfig` は CSRF を無効にしているので、ここでは `csrf()` は不要です。

> 💡 **ロールバックが効く条件**: この `@Transactional` ロールバックは、`MockMvc` がテストと同じスレッド・同じトランザクションで動くから成立します。`@SpringBootTest(webEnvironment = RANDOM_PORT)` で実サーバを立て、`TestRestTemplate` などの HTTP クライアントで叩く構成では、リクエストが別トランザクションになり、テストの `@Transactional` ではロールバックされません（その場合はテスト後に明示的にデータを消します）。

### 🏃 Step 4: テストを実行する

MySQL コンテナを起動した状態で（`docker compose up -d`）、テストをまとめて実行します。

```bash
# すべてのテストを実行
./mvnw test
```

すべて green（成功）になれば、ロジック・Web 入出力・認証認可を含む通しの振る舞いが自動で保証されたことになります。以降、コードを変更してもこのテストを流せば、壊れていないかをすぐ確かめられます。

> 💡 **JDK 21 で出る Mockito の警告について**: テスト実行時に「Mockito is currently self-attaching ...」という警告がコンソールに出ることがあります（4-2-1）。これは将来の JDK に向けた注意で、テスト自体は問題なく成功します。入門段階では無害な警告として先に進んで構いません。

## ✨ まとめ

- 層に応じてテストを選ぶ。ロジックは **単体テスト** （Mockito・Spring 起動なし）、Web 入出力は **`@WebMvcTest`** + `MockMvc`、通しの振る舞いは **`@SpringBootTest`** （4-2）
- モック Bean は Spring Boot 4 では **`@MockitoBean`** （`@MockBean` は削除済み）。`@WebMvcTest` の POST には `.with(csrf())` が要る
- 認可（自分のタスクのみ）のような異常系こそテストで固定する。`@WithMockUser` で認証済み状態を作る
- 統合テストは本物の設定で JWT 発行・検証まで通す。`@Transactional` でテストごとに DB をロールバックする
