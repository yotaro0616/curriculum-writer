## あなたが書いた array.push() の裏で、何が起きているのか

JavaScript で配列に要素を追加するとき、あなたは何気なく `array.push(value)` と書いてきたはずです。1 万回呼んでも、10 万回呼んでも、特に意識せず動く。PHP の `$array[] = $value;` も同じです。挿入したい場所が末尾なら、ほぼ瞬時に処理が終わります。

ところが、もし配列の **先頭** に値を挿入したい場合はどうでしょうか。

```javascript
// 例: 配列の先頭に値を挿入
array.unshift(value);   // O(n)。要素数が増えるほど遅くなる
```

`unshift` は、要素数が 10 万件あれば 10 万件すべての位置をずらす操作を内部で行います。`push` が一瞬で終わるのに、`unshift` は要素数に比例して遅くなる。同じ配列という名前のデータ構造なのに、なぜこんな差が出るのでしょうか。

この差を理解するには、配列がメモリ上にどう並んでいるかという、配列の「正体」を知る必要があります。本セクションは、その正体を **配列** （array）と **連結リスト** （linked list）という対比で読み解いていきます。

## 配列：連続したメモリと添字アクセス

理論的な意味での **配列** とは、同じ型の要素を **メモリ上の連続した領域** に並べたデータ構造のことです。たとえば 4 byte の整数を 5 個並べた配列なら、メモリ上では 20 byte の連続領域を占めます。

```text
番地    : 1000  1004  1008  1012  1016
配列要素: [10]  [20]  [30]  [40]  [50]
添字    :  [0]   [1]   [2]   [3]   [4]
```

このとき、添字 `i` の要素がどこにあるかは、計算式で **直接** 求められます。

```text
要素のアドレス = 先頭アドレス + i × 1 要素のサイズ
              = 1000 + 3 × 4 = 1012   （添字 3 なら）
```

要素数 `n` がどれだけ大きくても、計算は掛け算 1 回と足し算 1 回だけです。これが配列の **ランダムアクセス O(1)** の正体です。何番目の要素でも、同じ時間で取り出せます。

一方、配列の中間に要素を挿入したり削除したりするのは大変です。配列の途中にある要素をずらす必要があるため、最悪で **O(n)** の時間がかかります。

```text
挿入前: [10][20][30][40][50]
                ↑ ここに 99 を挿入したい

挿入後: [10][20][99][30][40][50]
              ←─── 後ろの要素を 1 つずつずらした
```

要素を `n` 個ずらすには、最大で `n` 回のコピー操作が必要です。配列の **先頭** への `unshift` が遅いのも、まさにこのためです。

## 連結リスト：ノードとポインタで「つなぐ」

配列の弱点は「メモリが連続している」点でした。逆に、メモリ上の位置はバラバラでもよく、要素同士を「次はここにあるよ」というポインタで繋いでいけば、別のデータ構造が作れます。それが **連結リスト** （linked list、リンクトリスト）です。

連結リストでは、1 つの要素を **ノード** （node）と呼ばれる小さな構造で表します。各ノードは「値」と「次のノードへのポインタ」の 2 つを持ちます。

```text
[10|*]→[20|*]→[30|*]→[40|*]→[50|/]
 値 次   値 次  値 次   値 次   値 終端
```

最後のノードは「次のノードがない」ことを表す `null`（または `/`）を指します。先頭のノードへのポインタを保持しておけば、そこから順番にポインタを辿ることで全要素にアクセスできます。

連結リストでは、メモリ上のどこにノードがあってもかまいません。逆に、特定の位置の要素を直接取り出すことはできず、先頭から順に辿る必要があります。これが連結リストの **ランダムアクセス O(n)** の理由です。

一方で、リストの途中に要素を挿入するのは高速です。挿入したい位置の前後のノードのポインタを書き換えるだけで済むためです。

```text
挿入前: [10|*]→[20|*]→[30|*]
挿入  : 20 と 30 の間に 99 を入れたい

ステップ 1: 新ノード [99|*] を作り、次ポインタを 30 に向ける
           [99|*]→[30|*]
ステップ 2: 20 のポインタを 99 に向ける
挿入後  : [10|*]→[20|*]→[99|*]→[30|*]
```

挿入位置がわかっていれば、配列の何個分もの要素をずらす必要がなく、ポインタの書き換えだけで完了します。これが連結リストの **挿入 O(1)** （位置がわかっている場合）の正体です。

## 単方向・双方向・循環の 3 種類

連結リストには、ポインタの持ち方によっていくつかのバリエーションがあります。

**単方向リスト** （singly linked list）: 各ノードが「次のノードへのポインタ」だけを持つ。一方向にしか辿れません。

```text
[A|*]→[B|*]→[C|*]→[D|/]
```

**双方向リスト** （doubly linked list、二重連結リスト）: 各ノードが「次」と「前」の両方のポインタを持つ。両方向に辿れる代わりに、ポインタ用のメモリが 2 倍必要になります。

```text
[/|A|*]⇄[*|B|*]⇄[*|C|*]⇄[*|D|/]
 前 値 次
```

**循環リスト** （circular linked list）: 最後のノードの「次」が先頭ノードを指す。終端がなく、ぐるぐる回り続けることができます。OS のラウンドロビン方式のタスクスケジューリングや、音楽プレイヤーのリピート再生機能などで使われます。

```text
[A|*]→[B|*]→[C|*]→[D|*]
  ↑                  │
  └──────────────────┘
```

| 種類 | 特徴 | 主な用途 |
|---|---|---|
| 単方向リスト | ポインタ 1 つ。メモリ効率が良い | スタックの内部実装、シンプルなリスト |
| 双方向リスト | ポインタ 2 つ。前後どちらにも辿れる | ブラウザの履歴（戻る / 進む）、両端キュー（deque） |
| 循環リスト | 終端が先頭に戻る | ラウンドロビンスケジューリング、リピート再生 |

## 配列と連結リストの計算量比較

試験で問われやすいのが、配列とリストの計算量の比較です。次の表を頭に入れておくことが、データ構造の問題を解く土台になります。

| 操作 | 配列 | 連結リスト |
|---|---|---|
| 末尾アクセス（位置がわかる） | O(1) | O(n)（先頭から辿る必要あり。末尾ポインタを保持していれば O(1)） |
| 任意の添字アクセス（i 番目） | O(1) | O(n) |
| 末尾への挿入 | O(1)（領域に余裕がある場合） | O(1)（末尾ポインタがあれば） |
| 先頭への挿入 | O(n)（全要素をずらす） | O(1)（先頭ポインタを書き換えるだけ） |
| 中間への挿入（位置がわかる） | O(n) | O(1)（位置がわかっていれば） |
| 中間からの削除（位置がわかる） | O(n) | O(1) |
| メモリ使用量 | 要素数 × 要素サイズ | 要素数 ×（要素サイズ + ポインタサイズ） |

ポイントは「位置がわかっている」場合と「位置を探す」場合を区別することです。連結リストの挿入そのものは O(1) ですが、挿入したい位置を探すのに O(n) かかります。したがって「途中に挿入する」操作の全体コストは、配列もリストも O(n) になります。

> よくある誤解: 「配列は遅くて、リストは速い」は正確ではありません。アクセスパターン次第で速さは逆転します。要素の取り出しが中心なら配列、要素の挿入 / 削除が中心ならリストが有利、と覚えるのが安全です。

## JavaScript の Array、PHP の配列は「理論上の配列」ではない

ここまで「配列」を、メモリ上に連続して並ぶ理論上のデータ構造として説明してきました。しかし JavaScript や PHP の **配列** という名前のデータ型は、実際にはもっと柔軟で、内部実装は配列とハッシュテーブルのハイブリッドになっています。

たとえば JavaScript の `Array` は、添字に数値以外（文字列など）も使えますし、要素を飛ばして `arr[100] = 'x';` のように疎な配列も作れます。これは内部的に「数値添字なら高速な配列として、文字列添字や疎なケースではハッシュテーブルとして」動作させているためです。

```javascript
// 例: JavaScript の Array はハイブリッド構造
const arr = [];
arr[0] = 'a';       // 普通の配列として動く
arr[100000] = 'z';  // 0〜99999 を確保するのではなく、疎な構造に切り替わる
```

PHP の配列も「順序付き連想配列」として実装されており、添字に整数も文字列も使えます。一方、Java の `int[]` や C 言語の配列は、本セクションで説明した「メモリ上に連続して並ぶ理論上の配列」に近い実装です。

> 補足: 基本情報技術者試験で「配列」と問われたら、それは原則として理論上の配列（連続メモリ）を指します。JavaScript / PHP の `array` の実装上の挙動を持ち込むと正解からズレることがあるので、試験の文脈では「配列はランダムアクセス O(1)、中間挿入 O(n)」とドライに割り切って考えるのが安全です。

## 配列とリストの使い分け：実装の現場での判断基準

実務でどちらを使うかは、次の 3 つの観点で判断できます。

1. **アクセスパターン**: 添字で頻繁に要素を取り出すなら配列。先頭から順に辿るだけならリストでも十分
2. **挿入 / 削除の頻度と位置**: 中間や先頭への挿入 / 削除が頻繁ならリスト。末尾のみなら配列で十分
3. **要素数の予測可能性**: 要素数があらかじめわかっているなら配列の方がメモリ効率が良い。動的に増減するならリストが向く

たとえばあなたが書いてきた SQL の `SELECT` 結果を PHP の配列で受け取って `foreach` で順に処理する、という典型的なコードは「先頭から末尾まで順次走査するだけ」なので、配列でもリストでも本質的な差はありません。一方、ブラウザの履歴のように「現在地から前へ・後ろへ移動する」処理は、双方向リストが概念的にぴったりです。

## 要点

- **配列** （array）はメモリ上の連続領域に要素を並べる構造。ランダムアクセスは **O(1)** 、中間への挿入 / 削除は **O(n)**
- **連結リスト** （linked list）は要素同士を **ポインタ** で繋ぐ構造。ランダムアクセスは **O(n)** 、位置がわかれば挿入 / 削除は **O(1)**
- 連結リストには **単方向** ・ **双方向** ・ **循環** の 3 種類があり、双方向は前後の両方向に辿れるかわりにポインタ用メモリが 2 倍
- 配列 vs リストは「アクセスパターン中心か、挿入 / 削除中心か」で使い分ける
- JavaScript の `Array` や PHP の配列は内部実装上は配列とハッシュテーブルのハイブリッド。試験で問われる「配列」は理論上の連続メモリ配列を指す
- 連結リストの「ポインタを書き換えるだけ」という性質は、後に学ぶスタック・キュー・木・グラフなど他のデータ構造の土台になる
