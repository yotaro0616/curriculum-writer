## このセクションで学ぶこと

- マークアップ言語とデータ記述言語の違いと、それぞれの代表例
- HTML / XML / SGML の関係、JSON / YAML / CSV の用途の使い分け
- スキーマ検証・コメントの可否・ファイルサイズなど、形式選定の判断軸

本セクションは、Web 開発で日々書いてきた「タグ言語」「設定ファイル」「データ交換フォーマット」を整理する内容です。

## あなたが書いてきた HTML、JSON、YAML は、何が違うのか

普段あなたは、画面構造を `<div>` や `<section>` で組み立て、API レスポンスを `{"id": 1, "name": "Alice"}` のような JSON で受け取り、Docker Compose の設定を `services:` から始まる YAML で書いてきたはずです。

これらはどれも「データを表現する」ための言語ですが、目的と設計思想が異なります。HTML は **文書の構造** をタグで表すマークアップ言語、JSON は **プログラム間でやり取りするデータ** の表現、YAML は **人間が読み書きしやすい設定ファイル** の表現に特化しています。同じ「データの記述」でも、使う場面・解釈する側・許される表現が違うのです。

このセクションでは、これらの言語の系譜と使い分けを整理し、試験頻出の比較問題に強くなることを目指します。

## マークアップ言語とは

**マークアップ言語** （markup language）は、本文に **タグ** （マーク、印）を埋め込んで、データに構造や意味を付与する言語です。本文と構造を 1 つのファイルに混在させて記述します。語源は印刷業界の「マーク（赤入れ）」で、印刷物にどう組版するかを示す指示と元の文章を一緒に書く文化に由来します。

代表的なマークアップ言語: SGML、HTML、XML、Markdown

### SGML（祖先）

**SGML** （Standard Generalized Markup Language）は、現在広く使われている HTML や XML の **祖先** にあたる規格です。1986 年に ISO 標準化された汎用マークアップ言語で、印刷・出版・公文書の構造化のために設計されました。複雑すぎて Web の現場では普及せず、その後シンプル化された HTML と XML に取って代わられました。試験では「HTML と XML の祖先」と覚えておけば十分です。

### HTML

**HTML** （HyperText Markup Language）は、Web ページの構造を記述するための言語です。`<h1>`、`<p>`、`<a>` のようなタグで本文に意味を付与し、ブラウザが解釈して画面を描画します。

```html
<!-- 例: HTML5 のセマンティックタグ -->
<article>
  <header>
    <h1>ニュースのタイトル</h1>
    <time datetime="2026-05-19">2026 年 5 月 19日</time>
  </header>
  <p>本文がここに入ります。</p>
</article>
```

HTML5（2014 年 W3C 勧告）以降は、`<article>`、`<section>`、`<header>`、`<footer>`、`<nav>`、`<aside>` といった **セマンティックタグ** が追加され、文書構造を意味的に表現できるようになりました。これは検索エンジンの解釈精度や、スクリーンリーダーによるアクセシビリティ向上のために重要です。

### XML

**XML** （eXtensible Markup Language）は、データ交換のための汎用的なマークアップ言語です。1998 年に W3C で標準化されました。最大の特徴は **タグ名を自分で定義できる** ことです。

```xml
<!-- 例: XML による書籍データ -->
<?xml version="1.0" encoding="UTF-8"?>
<books>
  <book id="1">
    <title>基礎理論</title>
    <author>山田太郎</author>
    <price>2800</price>
  </book>
</books>
```

XML には豊富な周辺仕様があります。

| 仕様 | 役割 |
|---|---|
| XML スキーマ / DTD | XML 文書の構造を定義し、検証する仕様 |
| XPath | XML 文書内の特定の要素を指定する経路表現 |
| XSLT | XML を別の XML や HTML に変換するスタイルシート言語 |
| XML 名前空間 | 同名タグの衝突を防ぐためのスコープ管理 |

XML は厳密で機能豊富な反面、記述量が多くなりやすく、近年は同等の用途で JSON が選ばれることが増えています。ただし金融・公的システム・SOAP ベースの古い Web サービスでは依然として XML が使われています。

### Markdown

**Markdown** はマークアップ言語の一種ですが、HTML よりさらにシンプルな記号（`#`、`*`、`-`、`[]()` など）で文書構造を表します。GitHub の `README.md` やこの教材自体が Markdown で書かれており、HTML に変換されて配信されます。試験出題は少ないですが、現代の Web 開発では避けて通れない記法です。

## データ記述言語とは

**データ記述言語** （data description language）は、プログラムやシステム間でデータをやり取りするための、構造化された表現形式です。マークアップ言語と違って本文を持たず、純粋にデータ（キーと値、配列など）だけを表現します。

代表的なデータ記述言語: JSON、YAML、CSV、TSV、TOML

### JSON

**JSON** （JavaScript Object Notation）は、JavaScript のオブジェクトリテラル記法に由来するデータ表現形式です。2001 年頃に登場し、REST API のレスポンス形式として事実上の標準になっています。

```json
{
  "users": [
    {
      "id": 1,
      "name": "Alice",
      "age": 30,
      "active": true,
      "roles": ["admin", "editor"]
    }
  ]
}
```

データ型は **文字列・数値・真偽値・null・配列・オブジェクト** の 6 種類だけというシンプルさが特徴です。JavaScript の `JSON.parse()` / `JSON.stringify()` で簡単に変換でき、フロントエンドとバックエンドのデータやり取りに最適です。

| 強み | 弱み |
|---|---|
| シンプルで読み書きしやすい | コメントが書けない |
| JavaScript と相性が良い | スキーマ検証は別仕様（JSON Schema）が必要 |
| データサイズが XML より小さい | 末尾カンマや単一引用符を許さず、設定ファイル用途では書きにくい |

### YAML

**YAML** （YAML Ain't Markup Language）は、人間が読み書きしやすいことを最重視したデータ記述形式です。YAML 1.2（2009 年）が現行仕様で、インデントで階層を表現します。

```yaml
# 例: Docker Compose の設定
services:
  app:
    image: nginx:1.25
    ports:
      - "8080:80"
    environment:
      - NODE_ENV=production
    depends_on:
      - db
  db:
    image: mysql:8.0
```

設定ファイルとしての採用が広く、Docker Compose、Kubernetes、GitHub Actions、Ansible、Rails の設定など、Web 開発の周辺ツールで頻繁に登場します。コメント（`#` で始まる行）が書ける点が JSON との大きな違いです。

| 強み | 弱み |
|---|---|
| 人間が読みやすい | インデントが厳密でエラーが起きやすい |
| コメントを書ける | パースが JSON より重い |
| 設定ファイル用途に強い | データ交換用途では JSON より少数派 |

> 補足: JSON は YAML の **サブセット** （厳密には 1.2 仕様で）に該当するため、JSON ファイルはほぼそのまま YAML として読み込めます。

### CSV と TSV

**CSV** （Comma-Separated Values）は、カンマ区切りでデータを並べるシンプルな表形式ファイルです。Excel や Google スプレッドシートで開ける汎用形式として、データのエクスポート・インポートに広く使われます。

```text
id,name,age,active
1,Alice,30,true
2,Bob,25,false
```

**TSV** （Tab-Separated Values）は区切り文字がタブの版です。データにカンマが含まれることが多いケースで採用されます。

CSV / TSV の弱みは、ネストしたデータ構造を表現できない点と、文字エンコーディングや区切り文字のエスケープに方言が多い点です。

### TOML

**TOML** （Tom's Obvious, Minimal Language）は、Rust の `Cargo.toml` や Python の `pyproject.toml` で使われる設定ファイル形式です。YAML より厳密で、JSON よりコメントが書きやすい中間的な位置づけにあります。試験出題は少ないですが、現代の開発ツールで頻出するため知っておくと役立ちます。

## 形式の比較表

各形式の特徴を 1 枚にまとめます。試験対策として暗記しておきたい比較です。

| 形式 | 主な用途 | 読みやすさ | サイズ | コメント | スキーマ検証 |
|---|---|---|---|---|---|
| XML | 文書構造、データ交換 | 中 | 大 | 可 | XML Schema / DTD |
| JSON | API レスポンス | 中 | 小 | 不可 | JSON Schema（別仕様） |
| YAML | 設定ファイル | 高 | 中 | 可 | JSON Schema 流用可 |
| CSV / TSV | 表形式データ | 中（単純な表のみ） | 最小 | 不可 | なし |
| TOML | 設定ファイル | 高 | 中 | 可 | なし（厳密な型定義あり） |

## JSON vs XML

実務でも試験でも頻出の比較が **JSON vs XML** です。両者は同じ「データ交換」の用途で使われますが、設計思想が異なります。

| 観点 | JSON | XML |
|---|---|---|
| データ型 | 6 種類（文字列・数値・真偽値・null・配列・オブジェクト） | 文字列のみ（型は外部スキーマで補う） |
| 記述量 | 少ない | 多い |
| 名前空間 | なし | あり（複数の語彙を混在可能） |
| スキーマ検証 | 別仕様（JSON Schema） | 標準仕様（XML Schema / DTD） |
| JS との親和性 | 非常に高い | 低い |
| 採用が多い領域 | REST API、モバイル | 古い Web サービス、公的システム、SOAP |

近年の Web 開発では JSON が優勢ですが、XML はスキーマ検証や名前空間の機能で勝るため、厳密性が求められる業界（金融、医療、公的書類など）では今も使われています。

> よくある誤解: 「JSON はマークアップ言語」と言うのは誤りです。JSON はマークアップ言語ではなく **データ記述言語** です。マークアップ言語は本文にタグを埋め込んでマークするもので、JSON はそもそも本文を持ちません。試験ではこの区別がよく問われます。

## HTML と JSON / YAML の使い分け

最後に、HTML と JSON / YAML の根本的な違いを整理します。

| 観点 | HTML | JSON / YAML |
|---|---|---|
| 表現するもの | 文書の **構造** と **見た目** （+ CSS） | 純粋な **データ** |
| 主な利用者 | 人間（ブラウザを介して読む） | プログラム（パースして処理する） |
| 主な配信先 | ブラウザ | サーバ間、フロントエンド ↔ バックエンド |
| タグの定義 | 標準で固定（独自タグは制限あり） | キー名は自由 |

たとえばあなたが Laravel で REST API を作ったとき、ブラウザに直接見せるページは HTML で返し、フロントエンドの JavaScript が叩く API エンドポイントは JSON で返してきたはずです。これは「人間が読む文書 = HTML」「プログラムが処理するデータ = JSON」という使い分けの典型例です。

## 要点

- **マークアップ言語** （HTML、XML、SGML、Markdown）はタグで本文に構造や意味を付与する言語
- **SGML** は HTML と XML の祖先となる汎用マークアップ言語
- **HTML5** のセマンティックタグ: `<article>`、`<section>`、`<header>`、`<footer>`、`<nav>`、`<aside>`
- **XML** はタグ名を自分で定義できるデータ交換用マークアップ言語。**XML Schema / DTD** で構造定義、**XPath** で要素指定、**XSLT** で変換
- **データ記述言語** （JSON、YAML、CSV、TOML）はプログラム間でデータをやり取りするための形式
- **JSON** は 6 種類のデータ型をもつシンプルな表現。REST API の事実上の標準。コメント不可
- **YAML** はインデントで階層を表現する人間に優しい形式。Docker Compose、Kubernetes、GitHub Actions などの設定ファイル用途で広く使われる。コメント可
- **CSV / TSV** はカンマ / タブ区切りの表形式データ。ネスト不可
- **JSON vs XML** : JSON は軽量・JS と親和、XML は厳密・スキーマ検証と名前空間で勝る
