## あなたが書いた JavaScript の `var` と `let`、PHP の `&$x`、これらの違いは何なのか

普段あなたはコードを書きながら、いくつかの「曖昧なまま動かしてきた挙動」を経験してきたはずです。JavaScript で `var` と `let` のどちらを使うべきか、PHP の関数引数に `&$x` をつけると何が変わるのか、`if (0 == "0")` がなぜ `true` になるのか、TypeScript の型注釈は実行時に効くのか。

これらはすべてプログラム言語の **仕様** の話です。スコープのルール、値の渡し方、型システムの設計が、試験で定義として問われ、実務では「なぜこのコードが動かないか」の根拠になります。本セクションでは、Web 開発で書いてきた JavaScript・PHP・TypeScript の挙動を題材に、試験頻出の言語仕様用語を整理します。

## 変数のスコープ

**スコープ** （scope）とは、ある変数が参照できる範囲のことです。スコープを正しく扱えないと、思わぬ場所で変数が上書きされたり、参照できないはずの変数にアクセスできてしまったりします。

### グローバルスコープ・ローカルスコープ・ブロックスコープ

| スコープ | 範囲 | 例 |
|---|---|---|
| グローバルスコープ | プログラム全体 | ファイルのトップレベルで宣言した変数 |
| ローカルスコープ（関数スコープ） | 関数の内側だけ | 関数内で宣言した変数 |
| ブロックスコープ | `{ }` で囲まれたブロック内だけ | `if` や `for` のブロック内変数 |

JavaScript の `var` と `let` / `const` の違いは、まさにこのスコープの違いです。

```javascript
// 例: スコープの違い
function example() {
  if (true) {
    var x = 10;   // 関数スコープ: 関数全体で参照可能
    let y = 20;   // ブロックスコープ: if のブロック内だけ
  }
  console.log(x); // 10 が表示される
  console.log(y); // エラー: y is not defined
}
```

`var` は関数スコープのため `if` の外でも参照できますが、`let` / `const` はブロックスコープなので `if` を抜けると参照できません。現代の JavaScript では `let` / `const` の使用が推奨されており、`var` を使うコードは過去の遺産であることが多いです。

### 静的スコープと動的スコープ

スコープには、変数の名前解決をどのタイミングで行うかという別の軸もあります。

| 種類 | 名前解決のルール | 採用言語 |
|---|---|---|
| 静的スコープ（lexical scope、レキシカルスコープ） | ソースコード上の **記述位置** で決まる | JavaScript、Python、PHP、Java、C など現代のほとんどの言語 |
| 動的スコープ（dynamic scope） | 関数の **呼び出し元** の文脈で決まる | 古い Lisp、Perl のローカル変数（`local`）、Bash のシェル変数 |

静的スコープでは、関数を定義した場所のスコープが、その関数の中の変数名解決のルールを決めます。動的スコープでは、関数を呼んだ場所の状態によって変数の意味が変わります。動的スコープはデバッグが困難になりやすく、現代の主要言語はほぼすべて静的スコープを採用しています。

## 値渡しと参照渡し

関数に引数を渡すとき、**値そのものを渡す** のか、**値の場所（参照）を渡す** のかという区別があります。これは関数内で引数を書き換えたときに、呼び出し元に影響するかどうかに直結する重要な仕様です。

### 値渡し（call by value）

**値そのものを複製して渡す** 方式です。関数内で引数を書き換えても、呼び出し元の変数には影響しません。C の通常の引数渡しが典型例です。

```c
// 例: C の値渡し
void increment(int x) {
    x = x + 1;   // この変更は呼び出し元に伝わらない
}
// 呼び出し元の a = 10 は increment(a) 実行後も 10 のまま
```

### 参照渡し（call by reference）

**変数の場所（メモリアドレス）を渡す** 方式です。関数内で引数を書き換えると、呼び出し元の変数も変わります。C のポインタや PHP の `&$x` が代表例です。

```php
// 例: PHP の参照渡し
function increment(&$x) {
    $x = $x + 1;
}

$a = 10;
increment($a);
echo $a;   // 11 が表示される
```

### 「参照の値渡し」（JavaScript / Python / Java）

JavaScript・Python・Java といった現代の言語で混乱しやすいのが、**オブジェクト** （配列、ハッシュ、インスタンス）を引数として渡したときの挙動です。これらの言語では、**プリミティブ値** （数値、文字列、真偽値）は値渡し、**オブジェクト** は「参照の値渡し」になります。

```javascript
// 例: JavaScript の参照の値渡し
function modify(obj) {
  obj.name = "Bob";       // この変更は呼び出し元に伝わる
  obj = { name: "Carol" }; // この再代入は呼び出し元に伝わらない
}

const user = { name: "Alice" };
modify(user);
console.log(user.name);   // "Bob" が表示される
```

ここがポイントです。オブジェクトを渡すとき、関数は「オブジェクトを指す参照」のコピーを受け取ります。**参照そのものは値として渡されている** ため、関数内で引数に別のオブジェクトを再代入しても呼び出し元には伝わりませんが、参照先のオブジェクトの内部を書き換えれば呼び出し元にも影響します。

Java も同様で、「Java はすべて値渡しだが、オブジェクトの場合は参照を値として渡している」と説明されます。試験ではこの区別が問われやすいので注意してください。

> よくある誤解: 「JavaScript はオブジェクトを参照渡しで渡す」という説明は、厳密には不正確です。正確には「参照を値として渡している」（参照の値渡し）。試験用語としては「値渡し」「参照渡し」の 2 択で問われることが多いですが、実態は中間的だと理解しておくと混乱しません。

## 型付け: 2 つの独立した軸

プログラム言語の型システムは、しばしば「静的か動的か」「強いか弱いか」の 2 軸で語られます。この 2 軸は **独立している** ので、4 つの組み合わせがあり得ます。

### 静的型付け vs 動的型付け（チェックのタイミング）

| 種類 | 型のチェック時期 | 代表的な言語 |
|---|---|---|
| 静的型付け（static typing） | コンパイル時 | C、C++、Java、C#、Go、Rust、TypeScript |
| 動的型付け（dynamic typing） | 実行時 | Python、Ruby、PHP、JavaScript |

静的型付け言語では、変数や関数の引数・戻り値の型を宣言時に決め、コンパイラが型の整合性をチェックします。動的型付け言語では、変数に好きな型の値を入れることができ、型の不整合は実行時に初めて分かります。

### 強い型付け vs 弱い型付け（暗黙の型変換の許容度）

| 種類 | 暗黙の型変換 | 代表的な言語 |
|---|---|---|
| 強い型付け（strong typing） | 厳密に拒否、明示的な変換が必要 | Java、Python、Ruby、TypeScript |
| 弱い型付け（weak typing） | 暗黙の型変換を広く許容 | C、PHP、JavaScript |

JavaScript で `0 == "0"` が `true` になるのは、**弱い型付け** の典型です。比較演算子 `==` が文字列の `"0"` を数値の `0` に暗黙的に変換してから比較するためです。Python では `0 == "0"` は `False` を返し、暗黙の変換を行いません。

### 4 つの組み合わせ

2 軸を組み合わせると、主要言語は次のように分類できます。

| 言語 | 静的 / 動的 | 強い / 弱い |
|---|---|---|
| C | 静的 | 弱い |
| Java | 静的 | 強い |
| TypeScript | 静的 | 強い |
| Python | 動的 | 強い |
| Ruby | 動的 | 強い |
| JavaScript | 動的 | 弱い |
| PHP | 動的 | 弱い |

「JavaScript と PHP は動的かつ弱い型付け」「Java と TypeScript は静的かつ強い型付け」「Python と Ruby は動的かつ強い型付け」と覚えておくと、試験での区別がつきやすくなります。

## 型推論

**型推論** （type inference）は、変数や式の型を明示的に書かなくても、処理系が文脈から自動的に推測する仕組みです。静的型付けの安全性と動的型付けの記述の簡潔さを両立する技術として、現代の言語で広く採用されています。

```typescript
// 例: TypeScript の型推論
const x = 10;          // x は number 型と推論される
const name = "Alice";  // name は string 型と推論される
```

型推論が強力な言語: TypeScript、Kotlin、Swift、Rust、C# の `var`、Java の `var`（Java 10 以降）。

## 制御構造とイベント駆動

制御構造（順次・分岐・反復）は 2-2 で繰り返し触れてきました。ここでは試験で問われる用語を簡単に確認します。

| 用語 | 意味 |
|---|---|
| 順次（sequence） | 上から下に順に実行 |
| 分岐（selection） | `if` / `switch` で条件により実行を分ける |
| 反復（iteration） | `for` / `while` で繰り返し実行 |
| 手続き呼び出し | 関数 / メソッドを呼ぶこと |
| 再帰呼び出し | 関数が自分自身を呼ぶこと（2-2-3 で詳述） |

これらを組み合わせて手続き型のプログラムが構成されますが、現代の Web 開発では **イベント駆動** （event-driven）という考え方も重要です。

**イベント駆動** は、ユーザーのクリックやタイマー発火のような **イベント** を待ち受け、発生したタイミングで対応する関数（**コールバック関数** 、callback function）を呼ぶ実行モデルです。JavaScript の `addEventListener` がその典型で、Node.js のサーバや GUI アプリケーションの多くがこのモデルで動いています。

```javascript
// 例: イベント駆動の典型
button.addEventListener("click", () => {
  console.log("クリックされました");
});
```

試験では「イベント駆動とは何か」「コールバック関数とは何か」が頻出語として問われます。

## 要点

- **スコープ** にはグローバル・ローカル（関数）・ブロックの 3 種類。JavaScript の `var` は関数スコープ、`let` / `const` はブロックスコープ
- **静的スコープ** （現代の主要言語）は記述位置で名前解決、**動的スコープ** （古い Lisp、Bash）は呼び出し元の文脈で解決
- **値渡し** は値を複製して渡す。関数内の変更は呼び出し元に影響しない（C の通常引数、Java のプリミティブ）
- **参照渡し** はメモリアドレスを渡す。関数内の変更が呼び出し元に影響する（C のポインタ、PHP の `&$x`）
- JavaScript・Python・Java のオブジェクトは **「参照の値渡し」** 。オブジェクトの中身は変更可能だが、再代入は呼び出し元に伝わらない
- 型付けの 2 軸: **静的 / 動的** （チェック時期）と **強い / 弱い** （暗黙変換の許容度）は独立した概念
- **型推論** で静的型付けと記述の簡潔さを両立。TypeScript、Kotlin、Swift などで採用
- 制御構造の基本: **順次・分岐・反復** 。**イベント駆動** はイベントを待ち受けてコールバック関数を呼ぶ実行モデル
