## あなたが書いた JavaScript と SQL は、本当に「同じ種類の言語」なのか

普段あなたは、フロントエンドで JavaScript、バックエンドで PHP、データ取得で SQL、画面構造の記述で HTML、設定ファイルで YAML や JSON を書いてきたはずです。すべて「プログラムを書いている」感覚で扱っていますが、実はこれらは設計思想がまったく異なる別種の言語たちです。

たとえば、ある条件のレコードを取り出す場面を考えます。PHP では次のように **手順を書きます**。

```php
// 例: 手順を 1 つずつ記述する
$results = [];
foreach ($users as $user) {
    if ($user->age >= 20) {
        $results[] = $user;
    }
}
```

一方 SQL では、**欲しいものを宣言します**。

```sql
-- 例: 結果のかたちを宣言する
SELECT * FROM users WHERE age >= 20;
```

PHP は「配列を 1 件ずつ調べて、条件に合ったら結果配列に詰めろ」と **手順** を指示しています。SQL は「年齢が 20 以上のユーザーをくれ」と **結果** を宣言し、どう取得するかは DB エンジンに任せています。同じ目的を達成するコードでも、立っているレイヤがまったく違うのです。

このセクションでは、こうした言語の分類軸を整理します。あなたが書いてきた言語たちが、どの軸の上に乗っているかを地図化することがゴールです。

## 機械語・アセンブリ言語・高水準言語

まず、抽象度の階層から見ていきます。コンピュータが直接実行できるのは **機械語** （machine code）だけです。機械語は 0 と 1 の並びで、CPU の命令セットに対応する数値列です。人間が直接書くのは現実的ではありません。

そこで、機械語の各命令にニーモニック（短い英語の略号）を割り当てた **アセンブリ言語** （assembly language）が登場します。`MOV`、`ADD`、`JMP` のような命令を並べて書きます。アセンブラ（後述）が機械語に 1 対 1 で変換します。

さらに人間に近い表記で書ける言語が **高水準言語** （high-level language）です。C、Java、Python、PHP、JavaScript など、現代のプログラム言語のほとんどがこの層に属します。1 行で複数の機械語命令に展開され、可読性と生産性が大きく上がります。

| 抽象度 | 例 | 特徴 |
|---|---|---|
| 機械語 | `10110000 01100001` | 0 と 1 の並び。CPU が直接実行 |
| アセンブリ言語 | `MOV AL, 61h` | 機械語にニーモニックを付けた表記 |
| 高水準言語 | `int x = 97;` | 人間の言葉に近い表記。CPU 非依存 |

「低水準」は CPU やハードウェアに近いという意味で、品質が低いという意味ではありません。OS のカーネルやデバイスドライバ、組み込み機器の一部では今でも C やアセンブリ言語が現役です。

## 4 つのパラダイム

高水準言語は **パラダイム** （paradigm、設計思想）によってさらに分類されます。試験で問われる主要なパラダイムは次の 4 つです。

### 手続き型（procedural）

順次・分岐・反復という制御構造を組み合わせて、処理の手順を順に記述するスタイルです。コードは関数（手続き）に分割され、関数同士が値をやり取りしながら全体の処理を進めます。

代表的な言語: C、Pascal、BASIC、FORTRAN、初期の PHP

```c
// 例: C による配列合計
int sum = 0;
for (int i = 0; i < n; i++) {
    sum = sum + arr[i];
}
```

最も歴史が古く、CPU の動作（命令を 1 つずつ実行する）に素直に対応するパラダイムです。

### オブジェクト指向（object-oriented）

データ（属性）とその操作（メソッド）を **オブジェクト** という単位にまとめ、オブジェクト同士のメッセージのやり取りで処理を組み立てるスタイルです。**カプセル化** （データと操作を 1 つにまとめ外部から隠す）、**継承** （既存のクラスを拡張する）、**ポリモーフィズム** （同じインタフェースで異なる実装を切り替える）の 3 つが基本概念です。

代表的な言語: Java、C#、C++、Ruby、現代の PHP（Laravel 等）、TypeScript

```php
// 例: PHP によるクラス定義
class User {
    private string $name;

    public function __construct(string $name) {
        $this->name = $name;
    }

    public function greet(): string {
        return "Hello, " . $this->name;
    }
}
```

Laravel の Eloquent モデルや Blade コンポーネントは、まさにオブジェクト指向の上に構築されています。

### 関数型（functional）

**関数** を第一級オブジェクト（変数に代入したり、引数として渡したり、戻り値として返せる対象）として扱い、**副作用** （関数の外の状態を変えること）を避けて、入力から出力への変換を組み合わせるスタイルです。同じ入力に対して常に同じ出力を返す **純粋関数** が中心になります。

代表的な言語: Haskell、Lisp、OCaml、F#、Scala（関数型寄り）、Erlang

```javascript
// 例: 関数型風の JavaScript
const doubled = [1, 2, 3, 4, 5]
  .filter(x => x % 2 === 0)
  .map(x => x * 2);
```

JavaScript や Python は手続き型・オブジェクト指向・関数型の要素を併せ持つマルチパラダイム言語で、`map` / `filter` / `reduce` のような高階関数を活用すると関数型風の書き方ができます。

### 論理型・宣言型（declarative）

**何を求めるか** を宣言し、**どう求めるか** は処理系に任せるスタイルです。手順ではなく結果のかたちを書きます。

代表的な言語: SQL、Prolog、HTML（広義の宣言型）、CSS

```sql
-- 例: 売上集計クエリ
SELECT user_id, SUM(amount) AS total
FROM orders
WHERE created_at >= '2026-01-01'
GROUP BY user_id;
```

冒頭の例で見たとおり、SQL は宣言型の典型です。`SELECT` と `WHERE` で「欲しい結果」を宣言するだけで、どのインデックスを使ってどう走査するかは DB エンジン（オプティマイザ）が決めます。

> 補足: Prolog は論理型の代表で、事実とルールを宣言すると処理系が論理的な推論で答えを導き出します。試験で「論理型言語の例は？」と問われれば Prolog です。

## パラダイムの比較表

| パラダイム | 何を書くか | 代表例 | キーワード |
|---|---|---|---|
| 手続き型 | 処理の手順 | C、Pascal、BASIC | 順次・分岐・反復、関数 |
| オブジェクト指向 | オブジェクト間のやり取り | Java、C#、PHP、Ruby | カプセル化、継承、ポリモーフィズム |
| 関数型 | 関数の合成 | Haskell、Lisp、OCaml | 純粋関数、副作用なし、第一級関数 |
| 論理型・宣言型 | 求めたい結果や事実 | Prolog、SQL、HTML | 宣言、結果指向 |

実際の言語の多くは複数のパラダイムを混ぜた **マルチパラダイム言語** です。Python、JavaScript、Scala、Kotlin、Rust などはいずれも手続き型と関数型、オブジェクト指向の機能を併せ持ちます。

## スクリプト言語と JIT 言語

パラダイムとは別の軸として、**実行方式** による区分もあります。**スクリプト言語** （scripting language）はソースコードを直接インタプリタが解釈実行する言語で、Python、Ruby、伝統的な PHP、シェルスクリプトなどが該当します。コンパイルの待ち時間がなく、対話的に試しながら書けるのが強みです。

一方、JavaScript や現代の Java、.NET のように、いったん中間コード（バイトコード）に変換してから実行時に部分的に機械語化する **JIT** （Just-In-Time）方式の言語もあります。詳細は次のセクション 2-3-2 で扱います。

## 「JavaScript は何型？」への答え

試験では選択肢を絞るために、しばしば「JavaScript はオブジェクト指向言語」「Python はオブジェクト指向言語」のような形でラベリングされます。これは半分正しく、半分は実態とずれています。

JavaScript は手続き型のコード（順次・分岐・反復）も、オブジェクト指向のコード（クラスと継承）も、関数型のコード（高階関数、不変データ）もすべて書けるマルチパラダイム言語です。実務では、React のコンポーネントは関数型寄り、Node.js のサーバ実装はオブジェクト指向寄り、jQuery 時代のコードは手続き型寄り、というように、現場ごとに優勢なスタイルが変わります。

> よくある誤解: 「JavaScript = オブジェクト指向」と単純に覚えると、実は関数型寄りの設計が求められる現場で違和感を覚えます。試験ではマルチパラダイムという表現も出るので、「オブジェクト指向と関数型の両方の特徴を持つ」と理解しておくと安全です。

## 要点

- 抽象度の階層は **機械語 → アセンブリ言語 → 高水準言語** 。CPU が直接実行できるのは機械語だけ
- **手続き型** （C、Pascal）は順次・分岐・反復で手順を記述する古典的なパラダイム
- **オブジェクト指向** （Java、C#、現代の PHP、TypeScript）はカプセル化・継承・ポリモーフィズムの 3 本柱
- **関数型** （Haskell、Lisp、OCaml）は副作用を避け、関数を第一級オブジェクトとして扱う
- **論理型・宣言型** （Prolog、SQL、HTML）は何を求めるかを宣言する。SQL の `SELECT` が宣言型の典型
- **スクリプト言語** （Python、Ruby、PHP）は中間コードを介さず実行、**JIT 言語** （JavaScript、Java）は実行時に機械語化
- 現代の言語の多くは **マルチパラダイム** 。JavaScript・Python は手続き型・OOP・関数型を併せ持つ
