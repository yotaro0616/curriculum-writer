## あなたの JavaScript は、なぜ 0.30000000000000004 を返すのか

ブラウザの開発者ツールで一度試してみてください。

```javascript
// 例: ブラウザのコンソールで実行
console.log(0.1 + 0.2);
// → 0.30000000000000004
```

`0.1 + 0.2` が `0.3` ではなく `0.30000000000000004` になります。これは JavaScript のバグではありません。Python でも PHP でも Java でも、ほとんどのプログラミング言語で同じ結果になります。

原因はコンピュータが小数を表現する方式にあります。コンピュータは 2 進数で小数を扱うため、10 進数の `0.1` を正確に表現できないのです。本セクションでは、この現象の正体である **浮動小数点数** の仕組みを掘り下げます。

## 符号付き整数：2 の補数表現

`-5` のようなマイナスの値を 2 進数でどう表現するでしょうか。最初に思いつくのは「先頭のビットを符号として使う」方法で、これを **符号ビット方式** （絶対値表現）と呼びます。

```text
8 bit の例:
 5 = 00000101  （先頭が 0 なので正）
-5 = 10000101  （先頭が 1 なので負）
```

しかしこの方式には弱点があります。まず `+0` と `-0` の 2 つの 0 が存在してしまう。そして加算回路を作るときに、符号を別途処理する複雑なロジックが必要になる。

この問題を解決するのが **2 の補数** （two's complement）表現で、現代のほぼすべてのコンピュータが採用しています。

**2 の補数の作り方**:

1. 元の値を 2 進数で表現する
2. すべてのビットを反転（0 と 1 を入れ替え）する
3. 1 を足す

10 進数の `5` を 8 bit で表現すると `00000101` です。`-5` を求める手順は次のとおりです。

```text
ステップ 1: 5 を 2 進数で書く     →  00000101
ステップ 2: ビットを反転する       →  11111010
ステップ 3: 1 を足す               →  11111011
```

検算してみましょう。`00000101 + 11111011 = 1 00000000` となり、8 bit の範囲内では `00000000`（0）になります。つまり `5 + (-5) = 0` が成立します。

この方式の良いところは、**減算を加算で実現できる** ことです。`8 - 5` を計算する代わりに `8 + (-5)` を計算でき、CPU の回路を単純化できます。

| ビット数 | 符号あり範囲（2 の補数） | 符号なし範囲 |
|---|---|---|
| 8 bit | -128〜127 | 0〜255 |
| 16 bit | -32,768〜32,767 | 0〜65,535 |
| 32 bit | -2,147,483,648〜2,147,483,647 | 0〜4,294,967,295 |

MySQL の `INT` の範囲（-2,147,483,648 〜 2,147,483,647）は、まさに 32 bit の 2 の補数の範囲です。

## 小数の表現：固定小数点数と浮動小数点数

整数だけでなく小数も 2 進数で扱う必要があります。2 進数で小数を表す方法は 2 つあります。

**固定小数点数** （fixed-point）は、ビットの中で小数点の位置を固定する方式です。たとえば 8 bit のうち上位 4 bit を整数部、下位 4 bit を小数部に割り当てれば、`5.25` という値を `0101.0100` と表現できます（下位 4 bit の `0100` は 1/4 = 0.25 を意味します）。

| 2 進数の小数 | 10 進数 |
|---|---|
| 0.1 | 1/2 = 0.5 |
| 0.01 | 1/4 = 0.25 |
| 0.001 | 1/8 = 0.125 |
| 0.0001 | 1/16 = 0.0625 |

固定小数点数は表現できる範囲が狭く、宇宙の質量から原子の重さまで扱うような科学計算には不向きです。そこで広く使われているのが **浮動小数点数** （floating-point）です。浮動小数点数は数を「**符号** ・ **指数** ・ **仮数**」の 3 つに分解して表現します。

```text
±仮数 × 基数^指数
```

たとえば 1,234.56 を浮動小数点で表すと `+1.23456 × 10³` のような形になります。これは科学技術計算で使われる指数表記（`1.23456e3`）と同じ考え方です。

---

## IEEE 754 規格

浮動小数点数の表現方法は **IEEE 754** という国際規格で標準化されており、現代のほぼすべての CPU と言語がこれに従います。

**単精度** （single precision、32 bit）の内訳:

| 部分 | ビット数 | 役割 |
|---|---|---|
| 符号部 | 1 bit | 0 = 正、1 = 負 |
| 指数部 | 8 bit | 2 の何乗かを表現（バイアス 127） |
| 仮数部 | 23 bit | 小数の有効桁を表現 |

**倍精度** （double precision、64 bit）は、符号部 1 bit + 指数部 11 bit + 仮数部 52 bit の構成です。JavaScript の `Number` 型や Java の `double` 型は倍精度を採用しています。

倍精度では約 15〜17 桁の有効数字を扱えますが、それでも 10 進数の小数を完全には表現できません。`0.1` を 2 進数で表すと `0.00011001100110011...` という無限循環小数になるためです。

> よくある誤解: 浮動小数点数の誤差は「コンピュータの精度が悪いから」起きるのではなく、「10 進数の有限小数が 2 進数では無限小数になる」という基数の違いから本質的に発生します。お金の計算など正確性が必要な場面では、固定小数点数（DECIMAL 型）や整数で「セント単位」で扱うのが定番の対処法です。

## 計算で発生する 4 つの誤差

浮動小数点演算では、次の 4 種類の誤差が試験頻出です。

**桁あふれ** （オーバフロー / アンダフロー）: 表現できる範囲を超えてしまう誤差。32 bit 符号あり整数で 2,147,483,647 + 1 を計算すると、結果が -2,147,483,648 になってしまう現象が典型例です。

**丸め誤差** （rounding error）: 仮数部に収まらない下位の桁を切り捨て・四捨五入することで生じる誤差。`0.1 + 0.2 = 0.30000000000000004` はこれの代表例です。

**桁落ち** （loss of significance）: ほぼ等しい 2 つの数の引き算で、有効桁が大きく失われる現象。`1.234567 - 1.234566 = 0.000001` のように、有効桁 7 桁が 1 桁になってしまうケースです。

**情報落ち** （loss of information）: 絶対値が大きく異なる数同士の加減算で、小さい方の値が無視される現象。たとえば `10⁸ + 10⁻⁸` のような計算で、指数を合わせる過程で `10⁻⁸` の情報が事実上失われます。

---

## 要点

- 負の整数は **2 の補数** で表現する。作り方は「ビット反転 → 1 を足す」
- 8 bit 符号あり整数の範囲は **-128〜127**、32 bit 符号あり整数の範囲は **-2,147,483,648〜2,147,483,647**
- 小数の表現には **固定小数点数** と **浮動小数点数** の 2 種類がある
- 浮動小数点数は **IEEE 754** 規格で、単精度 32 bit（符号 1 + 指数 8 + 仮数 23）、倍精度 64 bit（符号 1 + 指数 11 + 仮数 52）
- 浮動小数点の誤差には **桁あふれ・丸め誤差・桁落ち・情報落ち** の 4 種類がある
- 金額計算など正確性が必要な場面では浮動小数点数ではなく整数や DECIMAL 型を使う
