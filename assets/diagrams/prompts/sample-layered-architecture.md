# sample-layered-architecture

## プロンプト本文

```
技術解説用の俯瞰図（メンタルモデル）を作成してください。概念 Section 冒頭のサマリー図で、一目で要点が伝わることを最優先します。

【ユーザーストーリー】
Laravel 経験者の読者として、Controller / Service / Repository の3層が「それぞれ何を担当し、どんな順で連携するか」を一目で掴みたい。なぜなら Laravel では Controller と Model が中心で、間に Service 層を挟む構成に馴染みがないから。

【要件（描くもの）】
- 上部に見出しを大きく1行: 「各層が責務を分担し、上から下へ処理を渡す」
- 中央に3階建ての建物。上から順に階を積む: 最上階「Controller」、中階「Service」、下階「Repository」。各階にその役割を表すアイコン（Controller=受付カウンター、Service=歯車、Repository=書類棚）を置く
- 建物の土台（地下）に「DB」を倉庫アイコンで描く
- 左上から「リクエスト」のラベル付き矢印が最上階に入り、各階を上から下へ通って DB まで降りる流れを1本の矢印で示す。この流れの矢印をオレンジで強調
- 視線が上から下へ流れる構図。要素はこれだけ、ごちゃつかせない

【レイアウト（設計図。配置の指針としてのみ使い、罫線・記号・ASCIIの文字そのものは描かない）】
        各層が責務を分担し、上から下へ処理を渡す
  リクエスト ─┐
              ▼
       ┌──────────────┐
       │  Controller   │  (受付カウンター)
       ├──────────────┤
       │   Service     │  (歯車)
       ├──────────────┤
       │  Repository   │  (書類棚)
       └──────┬───────┘
              ▼
         ┌─────────┐
         │   DB     │  (倉庫)
         └─────────┘

【スタイル】
- フラットデザイン・インフォグラフィック風。影・グラデーション・写実は避ける
- 白背景(#FFFFFF)。基調色 #007396（ティール寄りの青）。リクエストが上から下へ流れる矢印のみ #ED8B00（濃いオレンジ）で強調
- クリーンなアウトライン線画、大きく読みやすいラベル、16:9 横長レイアウト

【受け入れ条件】
- 読者が3秒で「3つの層が上から下へ積まれ、リクエストが上から入って下へ流れる」と言える
- Controller / Service / Repository / DB の並び順が分かる

【描く文字の制約】
画像内に描いてよい文字は次のラベルだけ: 「各層が責務を分担し、上から下へ処理を渡す」「リクエスト」「Controller」「Service」「Repository」「DB」。上記の【ユーザーストーリー】【要件】【受け入れ条件】などの説明文は設計指示であり、画像内には描かない。指定ラベル以外の文字・英単語・記号・ふりがな・カタカナ・ロゴ・マスコットも描かない。
```
